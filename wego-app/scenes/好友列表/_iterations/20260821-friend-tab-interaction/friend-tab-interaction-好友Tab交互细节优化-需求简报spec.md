# 需求简报 spec：好友Tab交互细节优化

**迭代ID**：`friend-tab-interaction`
**创建日期**：2026-08-21
**主场景**：好友列表
**关联场景**：无
**状态**：awaiting-brief-confirmation
## 目标

在已恢复到最新代码的好友tab基础上，按最新交互设计工作流补全交互闭环与必要状态：好友新增与删除形成首尾闭环并以 localStorage 真实落盘（不再内存直 push 即丢），补齐列表加载态与存储失败态，完善空/搜索空结果引导，让单个好友列表场景的浏览、搜索、排序、增删体验完整可验收。

### 纳入范围（做）

- 浏览好友列表：字母/分组两种排序 + 右侧悬浮索引定位
- 切换排序：导航栏右侧入口在字母/分组排序间切换，索引随之更新
- 搜索过滤：按昵称实时过滤，命中高亮，清空恢复列表
- 添加好友：全屏表单提交后写入 localStorage 持久化并刷新列表
- 删除好友：列表内删除入口，删除后同步更新 localStorage 与列表
- 空状态引导：列表空 / 搜索无结果均展示可感知的引导与返回入口
- 加载态：进入 tab 时以本地演示延迟呈现列表加载表现
- 失败态：本地存储写入异常时提示失败并给出重试/关闭反馈

### 排除范围（不做）

- 好友详情页与相册浏览
- 后端持久化（仅 localStorage 本地存储）
- 扫码/名片/通讯录等无真实数据源的新增来源
- 其他 tab 场景

### 入口

- 底部导航栏「好友」tab（haoyou），点击进入好友列表主页面

### 关键路径

- [P1] 浏览与定位：进入好友tab → 初始加载呈现列表（默认字母排序）→ 右侧索引点击或滚动 → 定位到对应分组
- [P1] 搜索：搜索框输入关键词 → 实时过滤匹配昵称并高亮 → 无结果展示空结果引导 → 清空恢复完整列表
- [P1] 添加好友：导航栏右侧新建入口 → 全屏表单填写昵称/分组/来源 → 校验必填 → 提交写入 localStorage → toast 反馈 + 列表新增且刷新后仍保留
- [P1] 删除好友：列表项露出删除入口 → 确认删除 → 移除该项并更新 localStorage → 列表与索引同步刷新
- 排序切换：导航栏右侧排序入口 → 字母/分组排序切换 → 列表与索引重新分组

### 原型边界

| flow_id | 模式 | 可见结果 |
| --- | --- | --- |
| `friend-list-browse` | `functional` | 用户进入好友tab看到列表，可切换排序、搜索、右侧索引定位，并看到初始加载表现 |
| `friend-add` | `functional` | 用户提交添加表单后看到成功 toast，列表新增好友，刷新页面后好友仍在（localStorage 落盘） |
| `friend-delete` | `functional` | 用户删除好友后该项从列表移除，刷新后不再出现，列表与索引同步更新 |

### 状态

每个状态需明确「进入条件 + 可感知结果」，覆盖加载态 / 空态 / 失败态等交互状态。

- loading：进入好友tab且数据读取中 → 呈现列表加载占位表现，读取完成过渡到浏览态
- list-ready：数据就绪 → 默认字母排序展示好友列表 + 右侧悬浮索引，可滚动与定位
- sort-by-letter：切换至字母排序 → A-Z + # 分组，右侧索引显示字母
- sort-by-group：切换至分组排序 → 按自定义分组聚合，右侧索引显示分组名
- searching：搜索框输入关键词 → 实时过滤匹配昵称并高亮，隐藏分组标题与索引
- search-empty：搜索无匹配结果 → 展示搜索无结果空状态与清空/返回引导
- empty：好友列表为空 → 展示列表空状态并引导通过新建入口产生数据
- add-form：打开添加好友全屏表单 → 填写昵称/分组/来源，必填校验，提交
- save-failed：本地存储写入失败 → 提示存储失败，提供重试/关闭反馈，列表保持原状
- submit-success：添加/删除成功 → 关闭表单，toast 反馈，列表与索引同步刷新

### 数据契约

- `friend`：friend_id, nickname, py_initial(拼音首字母), group_id, new_count(上新数), product_total(总商品数), avatar
- `group`：group_id, group_name
- `produce_flow`：添加好友表单提交是唯一真实写入通道（写入 localStorage）；删除好友从 localStorage 移除
- `initial_source`：首次无 localStorage 数据时，初始数据来源于 window.WEGO_PROTOTYPE_DB 的 friends/friendGroups；此后新增与删除均以 localStorage 写入结果为准；不得在场景内随机生成昵称或另起分组
- `persistence`：localStorage 本地存储，无后端

### 假设

- 数据初始来源于 window.WEGO_PROTOTYPE_DB 的 friends/friendGroups，仅在首次无 localStorage 记录时作为初始数据，之后新增/删除均落 localStorage
- 删除与新增均为真实交互流程，非初始来源依赖
- 加载/失败态通过本地演示延迟与异常分支呈现，不引入真实后端
