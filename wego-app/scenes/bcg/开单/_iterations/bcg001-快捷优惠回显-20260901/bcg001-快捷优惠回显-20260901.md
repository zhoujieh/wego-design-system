# 快捷优惠回显 需求规格说明

## 元信息

- **迭代 ID**：bcg001
- **主场景**：开单
- **关联场景**：无
- **创建日期**：2026-09-01
- **状态**：draft
- **输入来源**：用户在正式原型收银开单横版页面的浏览器批注及 2026-09-01 范围确认

---

## 目标（goal）

让店员在 Pad／桌面端开单时，无需重新打开设置面板，就能从底部六个快捷优惠入口直接看出每项是否已使用及当前选择结果，同时保持订单优惠金额与所选规则一致。

---

## 纳入范围（included）

- 调整 Pad／桌面端开单页底部的会员折扣、积分抵扣、优惠券、满减促销、整单优惠、整单抹零六个快捷操作入口；默认在主文案下方显示字体图标库中的加号。
- 使用快捷优惠后，以红色状态文案替换加号：会员折扣显示“xx折”，积分显示“扣xx积分”，优惠券显示“用x张”，满减显示“满x减x”，整单优惠显示用户选择的优惠方式，整单抹零显示用户选择的抹零方式。
- 已使用入口保持中性底色，不再使用绿色背景或绿色图标表达已使用状态；当前打开状态仍需可识别，但不得与已使用状态混淆。
- 优惠券设置补充使用张数和抵扣金额录入；两者确认后共同形成优惠券状态，抵扣金额进入订单金额计算，使用张数用于入口回显。
- 满减促销设置补充门槛金额和减免金额录入；确认后回显“满x减x”，减免金额进入订单金额计算。
- 整单优惠支持“每件折扣、整单折扣、每件优惠、整单优惠”四种方式，并录入对应折扣或优惠金额；确认后入口回显所选方式，订单金额按所选方式计算。
- 整单抹零支持“整数抹零、个位抹零、十位抹零”三种方式；分别去掉应付金额的小数、向下取整到十元、向下取整到百元，并将差额计入订单优惠。
- 清除任一快捷优惠后恢复默认加号，并撤销该项对订单金额及回显状态的影响。

---

## 不纳入范围（excluded）

- 不调整手机竖版开单页面的快捷优惠布局与交互。
- 不新增优惠券库、促销活动库或后台配置流程；优惠券张数、抵扣金额及满减金额均由当前开单操作录入。
- 不调整客户、商品、发货、收款、草稿及订单成功流程。
- 不修改设计系统组件、Token 或字体图标资源本体。

---

## 入口（entry_points）

- Pad／桌面端进入“工作台 → 收银开单”，底部订单汇总区始终展示六个快捷操作；点击任一快捷操作按钮打开该操作的设置内容，确认或清除后回到开单页并立即更新按钮下方状态及订单金额。

---

## 关键路径（critical_paths）

- [P1] Pad／桌面端进入收银开单 → 查看底部六个未使用快捷操作 → 每个主文案下方显示字体图标加号且按钮为中性状态 → 点击后可进入对应设置。
- [P1] 打开会员折扣或积分抵扣 → 录入并确认有效值 → 入口分别回显“xx折”或“扣xx积分”且使用红色文字 → 订单优惠金额同步更新。
- [P1] 打开优惠券 → 录入使用张数与抵扣金额并确认 → 入口回显“用x张” → 抵扣金额同步进入订单优惠。
- [P1] 打开满减促销 → 录入门槛金额与减免金额并确认 → 入口回显“满x减x” → 减免金额同步进入订单优惠。
- [P1] 打开整单优惠 → 选择四种优惠方式之一并录入对应折扣或金额 → 确认后入口回显所选方式 → 订单金额按该方式更新。
- [P1] 打开整单抹零 → 选择整数、个位或十位抹零 → 确认后入口回显所选方式 → 根据确认前的应付金额计算抹零差额并更新订单金额。
- 已使用任一快捷优惠 → 再次打开并点击清除 → 该项业务值归零、入口恢复加号和中性状态 → 订单金额撤销对应优惠。

## 原型边界（prototype_boundaries）

### show-quick-operation-status

- mode: functional
- visible_result: 六个快捷操作默认显示字体图标加号，使用后在相同位置显示已确认的红色业务状态文案，清除后恢复默认状态；已使用按钮不显示绿色。

### edit-coupon-and-promotion-details

- mode: functional
- visible_result: 用户可真实录入优惠券张数、优惠券抵扣金额、满减门槛和减免金额，确认后状态与订单金额同时更新。

### apply-order-discount-mode

- mode: functional
- visible_result: 用户可从四种整单优惠方式中选择并填写对应值，入口回显方式名称，订单金额按所选规则计算。

### apply-rounding-mode

- mode: functional
- visible_result: 用户可选择三种抹零方式，入口回显方式名称，应付金额按对应位数向下取整并展示真实抹零差额。

## 状态（states）

- 默认主态：Pad／桌面端进入开单且六项快捷优惠均未设置 → 六个入口主文案下方显示字体图标加号，按钮均为中性底色。
- 加载态：开单页正在读取现有订单与客户数据 → 沿用现有开单加载反馈；数据完成后根据真实订单优惠值展示加号或状态文案，不预置优惠状态。
- 失败态：现有订单或草稿数据读取失败 → 沿用现有失败提示和重试／关闭入口；未成功读取的数据不得显示为已使用优惠。
- 空状态：订单未添加商品或没有可优惠金额 → 快捷入口仍可见并显示默认加号；用户可从右侧商品库添加商品后再设置优惠，不能产生负应付金额。
- 未使用态：某项业务值为空或已清除 → 对应入口显示加号，不显示红色状态文案，按钮保持中性。
- 已使用态：某项设置已确认且产生有效业务结果 → 加号替换为该项红色状态文案，按钮仍保持中性底色，订单金额显示对应优惠结果。
- 编辑态：点击任一快捷操作 → 打开对应设置内容并回填当前值；取消或关闭不改变原值，确认后立即回到已使用态。
- 当前打开态：某项设置内容正在打开 → 当前入口提供非绿色的可识别打开反馈，不改变其他入口状态。
- 清除态：在设置内容中清除某项 → 该项值与选择方式复位，入口恢复加号，订单金额撤销该项优惠。
- 越界态：折扣、积分、优惠或抹零超过可用积分或当前可优惠金额 → 沿用或补充输入约束并给出可见提示，订单应付金额不得小于零。

## 数据契约（data_contract）

### quick_operation_status

- 字段：memberDiscount 为 0–100 的百分数；pointsUsed 为不超过客户可用积分的非负整数；couponCount 为非负整数；couponDiscount、promotionThreshold、promotionDiscount 为非负金额；discountMode 为 item-rate、order-rate、item-amount、order-amount 之一；discountValue 为对应折扣或金额；roundingMode 为 integer、ones、tens 之一。
- 产生入口：用户在六个快捷操作设置内容中真实录入或选择并点击确认。
- 展示位置：Pad／桌面端开单页底部对应快捷操作主文案下方，以及现有订单优惠与应付金额区域。
- 修改方式：再次打开对应快捷操作可修改；点击清除复位该项状态和金额影响。

### quick_operation_amount

- 字段：优惠券以 couponDiscount 计入优惠；满减以 promotionDiscount 计入优惠；每件折扣按每件会员价乘折扣率计算，每件优惠按商品总件数乘单件优惠金额计算，整单折扣按当前可优惠商品金额乘折扣率计算，整单优惠按录入金额计算；抹零差额根据其他优惠计算后的应付金额与所选取整结果计算。
- 产生入口：用户完成商品录入后，在对应快捷设置中确认业务值或方式。
- 展示位置：订单优惠合计、订单总价及快捷操作状态。
- 修改方式：修改或清除对应快捷设置时重新计算；计算结果最低为零且不得使应付金额为负数。

## 假设（assumptions）

- 金额和折扣回显沿用现有紧凑数字格式，整数不显示无意义小数，小数最多保留必要位数。
- “每件优惠”按订单商品总件数乘单件优惠金额计算；“每件折扣”和“整单折扣”均作用于会员价后的商品金额，但保留不同方式名称供店员识别。
- 当前打开反馈由设计阶段使用中性边框或表面层级表达，不新增绿色状态。
