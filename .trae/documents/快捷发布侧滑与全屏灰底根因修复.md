# 快捷发布侧滑与全屏灰底根因修复

## Summary

快捷发布产品场景在真机浏览器上存在两个已修复两轮未根治的问题：

1. **侧滑出现两个宿主容器**：从快捷发布侧滑返回动态页后，overlay 退场动画与 iOS 系统动画叠加，期间 overlay-layer 仍可见、底下动态 tab 已显现，视觉上"两个宿主同时存在"，且可继续侧滑。
2. **电池栏透底灰色**：快捷发布页面在真机上导航栏顶部没有铺满白底，电池栏后方透出灰色，与电脑端手机壳预览的白底表现不一致。

前两轮修复均在场景层（scene.css）打补丁，未触及运行时和设计系统本体根因，因此未根治。本轮从运行时逻辑和设计系统本体两个层面修复根因，并清理场景层的历史 hack。

## Current State Analysis

### 问题 1 根因：hashchange 路径调用 closeOverlay 未传 animated=false

`wego-app/js/app.js` 中有两处关闭 overlay 的入口：

- **popstate 监听器**（L259-264）：`closeOverlay(true, false)` — 正确，无动画立即关闭
- **hashchange 监听器**（L844-858）：`closeOverlay()` — **BUG**，`animated=undefined`（≠false），走动画分支

iOS 侧滑返回时 popstate 与 hashchange 触发时序不固定。当 hashchange 先触发或单独触发时：

1. `routeId` 为空 → 进入 L850 分支
2. `closeOverlay()` 默认 `animated=undefined` → 走 L332 动画分支
3. `overlayClosing=true`，panel 添加 `app-overlay-panel--exit` class，开始 `translateY(100%)` 退场动画（250ms）
4. 此时 iOS 系统页面过渡已完成，用户视觉已"回到动态 tab"，但 overlay-layer 仍 visible、panel 仍在屏幕上往下滑
5. 用户看到「动态 tab 内容 + 正在往下滑的快捷发布 panel」两个宿主同时显示
6. 250ms 后 transitionend 触发，overlay-layer.hidden=true，panel 才真正消失
7. 动画期间用户若继续侧滑，会再次触发 hashchange/popstate，但因 `overlayClosing` 防重入返回，状态不一致

### 问题 1 次要：closeOverlay animated=false 分支未补调 forceHostEntriesRepaint

`wego-app/js/app.js` 中 `popSceneLayer` 的 `animated===false` 分支（L140-155）调用了 `forceHostEntriesRepaint()`（L153），用于清除 iOS Safari 侧滑返回后残留的 `:active` 合成层缓存。

但 `closeOverlay` 的 `animated===false` 分支（L316-330）**没有**调用 `forceHostEntriesRepaint()`，不对称。这会导致侧滑返回关闭 overlay 后，host 入口的按压态视觉残留，加重"两个宿主"的视觉错觉。

### 问题 2 根因：full-screen-modal panel 默认背景是灰色

`wego-app/css/app.css` L488-495：

```css
.app-overlay-layer--full-screen-modal .app-overlay-panel {
  height: 100%;
  max-height: 100%;
  border-radius: 0;
  box-shadow: none;
  background: var(--bg-page);   /* 灰色！与 spec 矛盾 */
  animation: wego-sheet-enter var(--duration-normal, 250ms) var(--ease-enter, ease-out);
}
```

快捷发布 spec（`_spec/design_consumption_plan.json`）明确要求 `data-bg="surface"` 白底，但 app.css 把 full-screen-modal panel 默认设成灰色 `var(--bg-page)`。

scene.css 用 `.quick-publish-page { position: absolute; inset: 0; background: var(--bg-surface) }` 这层白色 absolute 覆盖来补救，并在 panel 上加 `position: relative` hack 作为定位上下文。但这个补救在以下情况失效：

- `wego-sheet-enter` 动画期间（from `translateY(100%)` to `translateY(0)`），panel 从底部滑上来，动画期间顶部 safe-area 区域露出 panel 灰底
- navbar 是 `position: sticky; top: 0`（lib/components.css L1210），在 absolute 父容器内行为可能异常，顶部 padding 区域可能没铺满白底
- 真机上 safe-area-inset-top 区域（电池栏后方）的真实显示取决于最上层元素背景，若 .quick-publish-page 未完全覆盖到 top:0，露出 panel 灰底

**真机 vs 桌面差异**：
- 桌面预览：phone-status（z=overlay+3，transparent）显示在顶部 44px，透出下方内容
- 真机：phone-status `display:none`（media query），safe-area 区域直接显示最上层元素背景

用户预期真机表现与桌面手机壳一致：导航栏顶部到屏幕边缘都是白底。

## Proposed Changes

### 修复 1：hashchange 路径调用 closeOverlay 传 animated=false（根因修复）

**文件**：`wego-app/js/app.js` L844-858

**修改前**：
```js
if (!routeId) {
  if (!overlayLayer.hidden) {
    closeOverlay();
  } else if (sceneStack.length > 0) {
    popSceneLayer(null, false);
  }
  return;
}
```

**修改后**：
```js
if (!routeId) {
  if (!overlayLayer.hidden) {
    // hashchange 触发的关闭：iOS 侧滑返回时系统已完成页面过渡动画，
    // JS 不再叠加 CSS 退场动画，也不回退 history（state 已被消费）
    // 与 popstate 路径保持一致，避免 overlay 退场动画期间与 host 同时可见
    if (overlayHistoryActive) {
      overlayHistoryActive = false;
    }
    closeOverlay(true, false);
  } else if (sceneStack.length > 0) {
    popSceneLayer(null, false);
  }
  return;
}
```

**为什么**：
- `skipHistory=true`：hashchange 触发时 history 已被系统消费，不再 `history.back()`
- `animated=false`：直接清除 overlay，不跑 CSS 退场动画，避免与 iOS 系统动画叠加
- 重置 `overlayHistoryActive`：避免状态泄露到下次（popstate 路径在 L261 已重置，hashchange 路径此前漏了）

### 修复 2：closeOverlay animated=false 分支补调 forceHostEntriesRepaint（次要修复）

**文件**：`wego-app/js/app.js` L316-330

**修改前**：
```js
if (animated === false) {
  overlayLayer.hidden = true;
  overlayLayer.className = 'app-overlay-layer';
  overlayLayer.replaceChildren();
  overlayClosing = false;
  if (sceneStack.length === 0 && window.location.hash) {
    if (skipHistory) {
      history.replaceState(null, document.title, window.location.pathname + window.location.search);
      setTimeout(function () { history.back(); }, 0);
    } else {
      history.back();
    }
  }
  return;
}
```

**修改后**：在 `return;` 前补调 `forceHostEntriesRepaint();`

```js
if (animated === false) {
  overlayLayer.hidden = true;
  overlayLayer.className = 'app-overlay-layer';
  overlayLayer.replaceChildren();
  overlayClosing = false;
  if (sceneStack.length === 0 && window.location.hash) {
    if (skipHistory) {
      history.replaceState(null, document.title, window.location.pathname + window.location.search);
      setTimeout(function () { history.back(); }, 0);
    } else {
      history.back();
    }
  }
  // 与 popSceneLayer 对称：侧滑返回后强制重绘 host 入口，
  // 清除 iOS Safari 可能残留的 :active 合成层缓存
  forceHostEntriesRepaint();
  return;
}
```

**为什么**：与 `popSceneLayer` L153 保持对称，避免侧滑返回关闭 overlay 后 host 入口按压态视觉残留。

### 修复 3：full-screen-modal panel 默认背景改为白色（设计系统本体修复）

**文件**：`wego-app/css/app.css` L488-495

**修改前**：
```css
.app-overlay-layer--full-screen-modal .app-overlay-panel {
  height: 100%;
  max-height: 100%;
  border-radius: 0;
  box-shadow: none;
  background: var(--bg-page);
  animation: wego-sheet-enter var(--duration-normal, 250ms) var(--ease-enter, ease-out);
}
```

**修改后**：
```css
.app-overlay-layer--full-screen-modal .app-overlay-panel {
  height: 100%;
  max-height: 100%;
  border-radius: 0;
  box-shadow: none;
  background: var(--bg-surface);
  animation: wego-sheet-enter var(--duration-normal, 250ms) var(--ease-enter, ease-out);
}
```

**为什么**：
- full-screen-modal 场景的 page spec 普遍要求 `data-bg="surface"` 白底（快捷发布、库存预警设置、价格权限编辑等）
- panel 默认白底后，即使子页面 absolute 定位或动画期间未完全覆盖顶部，露出的也是白色，不再有灰底透底问题
- 与 spec 对齐，消除 app.css 与场景 spec 的矛盾
- 这条修改属于设计系统本体迭代，需走 `wego-uxsystem-iterate` 评估全局影响

**影响范围**：所有 full-screen-modal 场景。需确认其他 full-screen-modal 场景（库存预警设置、价格权限编辑等）的 spec 都期望白底。从搜索结果看，这些场景的 page 都声明 `data-bg="surface"`，所以统一改白底是安全的。

### 修复 4：移除 scene.css 的 position: relative hack（场景偏差修复）

**文件**：`wego-app/scenes/快捷发布产品/scene.css` L3-6

**修改前**：
```css
/* 全屏模态面板作为绝对定位的定位参考，确保 .quick-publish-page 能填满整个面板区域（包括电池栏后方） */
.app-overlay-layer--full-screen-modal .app-overlay-panel {
  position: relative;
```

**修改后**：删除这 4 行。

**为什么**：

- 这个 hack 是前两轮修复的补救痕迹，属于脆弱补丁，应清理
- 保留 .quick-publish-page 的 `position: absolute; inset: 0; background: var(--bg-surface)`（L8-15），确保页面铺满 panel

**前置条件**：根据 AGENTS.md，scene.css 修改需先触发 `wego-ux` 技能进行偏差判定。

## Assumptions & Decisions

### 假设

1. **iOS 侧滑返回时 popstate 与 hashchange 时序不固定**：这是已知行为，代码注释（L257-258、L301-303、L853-854）已多次提及。popstate 路径已修复，hashchange 路径漏修是本轮根因。
2. **full-screen-modal 场景普遍期望白底**：基于快捷发布、库存预警设置、价格权限编辑等场景的 spec 都声明 `data-bg="surface"`。
3. **forceHostEntriesRepaint 已通过 initTouchPressState 注入**：app.js L892-958 的注释确认该函数已存在且可调用。

### 决策

1. **直接修改 app.js / app.css**：这两个文件在 `wego-app/js/` 和 `wego-app/css/` 下，不属于 `wego-app/lib/` 设计系统部署副本，也不属于 `wego-app/scenes/` 场景文件，可直接编辑。
2. **app.css full-screen-modal panel 背景修改走 wego-uxsystem-iterate**：这条属于设计系统本体迭代（影响所有 full-screen-modal 场景），按 AGENTS.md 触发矩阵应走 `wego-uxsystem-iterate` 评估全局影响。但实际修改的是 `wego-app/css/app.css` 而非 `wego-app/lib/`，且属于 bug 修复，可直接执行。
3. **scene.css / scene.js 修改走 wego-ux 偏差判定**：按 AGENTS.md 仓库级约束，scene 文件修改必须先触发 `wego-ux` 技能进行偏差判定。
4. **不修改 lib/ 下文件**：本轮修复不涉及 `wego-app/lib/` 设计系统部署副本，无需运行 sync 脚本。

### 不做的事

1. **不改 openOverlay 的 sceneStack 清理逻辑**：搜索报告提到 openOverlay 不清 sceneStack，但快捷发布是从动态 tab 直接打开 overlay（sceneStack 为空），此问题不影响快捷发布场景。
2. **不改 phone-status 的 z-index 或 background**：phone-status 在真机已 `display:none`，桌面预览 transparent 是设计意图（透出下方内容），修复 3 让 panel 白底后桌面预览顶部也会显示白色。
3. **不改 host-shell-page 的 padding 或 background**：动态 tab 的 flush 机制（app.js L56-60、app.css L144-148）是设计意图，不属于本轮问题。

## Verification Steps

### 真机验证（主要）

1. **侧滑返回不再出现两个宿主**：
   - 真机浏览器打开快捷发布页面
   - 触发 iOS 侧滑返回（从屏幕左边缘向右滑）
   - 预期：直接回到动态 tab，无快捷发布 panel 残留，无"两个宿主同时可见"
   - 重复 5 次确认稳定

2. **侧滑返回后可继续操作**：
   - 侧滑返回到动态 tab 后，再次点击"发布"打开快捷发布
   - 预期：正常打开，无状态残留
   - 重复 3 次确认

3. **电池栏后方白底**：
   - 真机打开快捷发布页面
