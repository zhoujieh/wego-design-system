# 设置 / 产品与笔记 — 设置项内容生成计划

## Summary

在 `wego-app` 静态 App 中新增"产品与笔记"设置子页面，承接用户提供的四组设置项（无标题组 + 商品 + 发布/转发 + 其他），包含 switch 开关与导航行两类 cell。入口已预留于"系统设置"场景列表（`data-entry-id="product-note"`，当前仅 toast），本任务将其接入为真实 `navigate` 跳转，并按 wego 标准流水线产出 `_spec/page_spec.json`、`_spec/design_consumption_plan.json`、`scene.js`、`scene.css`，更新 `routes.js`。

## Proposed Changes

### 1. 新建 `wego-app/scenes/产品与笔记/_spec/page_spec.json`

**what**：产出 page_spec，声明任务类型、场景、信息块、页面角色、宿主挂载、route_id。

**why**：wego 流水线硬性交接规则——无 page_spec 不进入设计消费。

**how**（关键字段）：
- `task_type`: `"design-system-consumption"`
- `scene_category`: `"system-setting"`（平台层通用偏好 + 即时生效开关，非业务对象规则编辑）
- `interaction_mode`: `"instant-apply"`（switch 即时切换；导航行 select 下钻）
- `app_target`: `{mode: "wego-app-scene", app_root: "wego-app", scene_folder: "wego-app/scenes/产品与笔记", runtime_entry: "scene.js", route_mode: "hash"}`
- `page_surfaces`：
  - `host-entry`（role: host-entry）：宿主入口——"一级入口：设置（点击进入系统设置页）"+"二级入口：产品与笔记（挂在设置下，点击打开主任务页）"两条独立信息块，`purpose` 声明二级入口在系统设置列表内视觉从属
  - `product-note-list`（role: primary-task-page）：产品与笔记设置主页，承接四组设置项
- `host_container`: `{tab: "my", entry_label: "设置", subentry_label: "产品与笔记", leaf_level: 2, entry_type: "cell", needs_host_entry_surface: true}`
- `route_id`: `"my-product-note"`
- `information_blocks`：按页面顺序列出四组设置项（无标题组、商品、发布/转发、其他）
- `component_intent`：cell-group 分组、cell+switch（即时开关）、cell+arrow（导航下钻）、cell+action-text+arrow（带状态文案的导航）、副标题内嵌 link（详情）
- `spec_refs`：引用 specs 下文案/布局/交互/视觉/动效五份规范

**why**：无 design_consumption_plan 不生成原型。

- `implementation_constraints`：

  - 默认内存状态，不持久化

### 3. 新建 `wego-app/scenes/产品与笔记/scene.js`

**what**：场景脚本，注册 `my-product-note` route，渲染四组设置项，绑定 switch 切换与导航 toast。

**why**：核心交付物。

**how**（结构参照系统设置 scene.js）：
- 顶部 `var STATE = { showProduct: true, showNote: true, smartPrice: true, textPriceOrder: true, keepAlbumOrder: false, hdUpload: true, hdTransfer: true, filterContact: true, foldDetail: false }` 内存状态
- `esc()` HTML 转义工具（复用系统设置写法）
- `switchMarkup(key, on)`：生成 `<div class="switch switch--on/off" data-switch-key="key" role="switch" aria-checked="..." tabindex="0"><div class="switch__thumb"></div></div>`
- `cellRowMarkup(item, isLastInGroup)`：根据 item.type 分支
  - `type: 'switch'`：`<div class="cell cell--single/double cell--bg-white [cell--divider-right-edge]">` + body(content + action(switch))，**不加 cell--clickable**
  - `type: 'navigate'`：`<button class="cell ... cell--clickable" data-entry-id="...">` + body(content + action([action-text] + arrow))
  - density：有副标题用 `cell--double`，无副标题用 `cell--single`
- `groupMarkup(group)`：`<div class="cell-group">` + 可选 `<div class="cell-group__title">` + `<div class="cell-group__content">` + rows
- `pageTemplate()`：`<section data-bg="page">` + navbar(back-icon + "产品与笔记") + phone-body + groups
- `window.WegoApp.registerScene({routeId: 'my-product-note', title: '产品与笔记', presentation: {type:'push', transition:'slide-left', coversTabBar:true}, template:'', init: function(ctx){...}})`
- `init` 内：
  - `render()`：`ctx.root.innerHTML = pageTemplate()` + `bind()`
  - `bind()`：
    - `[data-action="back"]` → `ctx.back()`
    - `[data-switch-key]` → click 切换：`STATE[key] = !STATE[key]`，更新 DOM class 与 aria-checked，可选 toast（如"已开启/已关闭"）
    - `[data-entry-id]` → click toast"该功能尚未接入原型"
    - `[data-action="detail"]`（副标题内详情链接）→ click `e.stopPropagation()` + toast"查看详情"
- 数据结构 `GROUPS`：四组，每组 `{title: '' | '商品' | '发布/转发' | '其他', items: [...]}`，items 含 `{id, title, subtitle, type, switchKey?, actionText?}`

### 5. 更新 `wego-app/js/routes.js`

**what**：新增 `my-product-note` route 配置。

**why**：scene 必须通过 routes.js 注册才能被 hash route 与 `ensureScript/ensureStyle` 加载。

**how**：
```js
{
  routeId: 'my-product-note',
  scene: '产品与笔记',
  script: './scenes/产品与笔记/scene.js',
  style: './scenes/产品与笔记/scene.css',
  entry: {
    tab: 'my',
    group: 'my-system-settings-internal',  // 不存在的容器，app.js mountRouteEntries 会 if(!group) return; 跳过宿主挂载
    label: '产品与笔记',
    type: 'cell'
  }
}
```
- `entry.group` 设为不存在的容器名，利用 app.js 第 304-305 行 `if (!group) return;` 优雅跳过宿主挂载，避免与系统设置内部入口重复
- 在 route 上方注释说明"该 route 为系统设置内部入口，不挂宿主"

### 6. 修改 `wego-app/scenes/系统设置/scene.js`

**what**：将 `product-note` 入口点击从 toast 改为 `ctx.navigate('my-product-note')`。

**why**：接入新场景。

**how**：修改第 190-194 行的 `[data-entry-id]` 点击绑定，区分 `product-note` 与其他入口：
```js
root.querySelectorAll('[data-entry-id]').forEach(function (row) {
  row.addEventListener('click', function () {
    var id = row.dataset.entryId;
    if (id === 'product-note') {
      ctx.navigate('my-product-note');
      return;
    }
    ctx.toast('该功能尚未接入原型');
  });
});
```

## Assumptions & Decisions

1. **场景目录名**：`产品与笔记`（中文业务语义，与用户表述一致）
2. **route_id**：`my-product-note`（与 `my-system-settings`、`my-price-management` 风格一致）
3. **入口接入方式**：独立 scene + `ctx.navigate`（方式 A，与价格权限管理一致），不在系统设置内用 full-screen-modal
4. **不挂宿主**：route 的 `entry.group` 指向不存在容器，利用 app.js 既有逃逸口，不改 app.js
5. **pagePattern**：`system-settings`（push + cell 为主；switch 作为 cell trailingSlot，不破坏范式；不选 biz-rule-config 因为这是平台偏好设置而非业务对象规则编辑，无统一保存收口）
6. **switch 交互**：即时生效（内存 state），不开 `cell--clickable`，点击切换 class + aria，不强制 toast（避免噪音）
7. **导航行交互**：toast"该功能尚未接入原型"（与系统设置一致，不实现下钻）
8. **详情链接**：副标题内 `<a>` 单独绑定 `stopPropagation` + toast
9. **不持久化**：默认内存状态，刷新后回到初始值（用户需求未明确要求持久化）
10. **不实现 wego-tests 验收**：本计划聚焦生成阶段；如需验收报告可后续追加
11. **初始开关状态**：严格按用户 HTML 标注（showProduct=on, showNote=on, smartPrice=on, textPriceOrder=on, keepAlbumOrder=off, hdUpload=on, hdTransfer=on, filterContact=on, foldDetail=off）
12. **组标题**：第 1 组无标题（不输出 `cell-group__title`），商品/发布-转发/其他三组有标题
