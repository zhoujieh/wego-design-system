基于现有 Token 体系，把页面边距档位从 `--layout-page-margin-none/sm/lg`（0/16/32px，3 档）重构为 `--layout-page-margin-m0/m8/m16/m32`（0/8/16/32px，4 档），并同步运行时规则命名（wego-design/SKILL.md 的 M1/M2 → M0/M16，扩展 M8/M32）、下游引用、参考文档、部署副本与生成文档。

## Assumptions & Decisions

### 决策 1：权威来源是 Token 体系 + SKILL.md，不是 specs/ 文档
用户明确纠正：`specs/布局与间距规范.md` 只是参考。Token 体系（`colors_and_type.css` + `css.json`）是页面边距值的权威源；`wego-design/SKILL.md` 是 M1/M2 布局模式命名的运行时权威源。`布局与间距规范.md` 跟着同步但不作为源头。

### 决策 2：范围只限"页面边距档位"，不动 spacer 原子体系
用户给的 4 档值（0/8/16/32px）与语义（通栏/长列表/内容少/白底+cell对齐）与 `--layout-page-margin-*` 完全对应。`--spacer-*` 15 档原子间距保持不变，80+ 处组件/场景消费零影响。

### 决策 3：Token 命名改为 `m0/m8/m16/m32`（与档位名一一对应）
理由（往未来看）：
1. 档位名 M0/M8/M16/M32 与 Token 名一一对应，消除文档档位名与 CSS Token 名之间的映射成本
2. 绝对值命名未来新增档位时无需重排相对级别（none/xs/sm/lg/xl 顺序易乱）
3. 保留 `--layout-page-margin-` 前缀，维持"页面边距"语义层，与通用 `--spacer-*` 区分
4. 当前全仓无人消费，改名零破坏成本
5. 命名风格与 `--spacer-{值}` 一致，降低消费方记忆负担

### 决策 4：SKILL.md 的 M1/M2 同步改为 M0/M16
M1/M2 是 SKILL.md 的运行时 `layout_pattern` 枚举值，与 Token 值（0/16px）绑定。Token 改名后若不同步 SKILL.md，会造成"Token 名 m0/m16"与"运行时模式名 M1/M2"断链。同步扩展 M8/M32 两档枚举，使四档体系在运行时规则层完整可达。

### 决策 5：M32 引用 cell 已有 `.cell--divider-center`，不扩范围改 form
cell 已具备 divider-center 能力（分割线右端与文本右缘对齐、不贴边），M32 规则直接引用。form 无等价能力，本次不扩展 form 组件（避免范围蔓延），在 M32 规则正文标注 form 待补 divider-center 能力。

### 决策 6：M8 开 --card（用户明确纠正）
M8=8px 介于通栏 M0（0px）与卡片 M16（16px）之间。用户明确指出"8px 的情况下通常都是要开 card 的"。M8 下 phone-body 8px 横向 padding，页面灰底，cell-group__content 开 --card（白底圆角卡片），cell 分割线用 `.cell--divider-right-edge`。语义是"长列表数据较多，需要更多横向空间，但仍用卡片容器保持分组节奏"。

### 决策 7：M32 不开 --card，理由是页面白底（非"避免双重 padding"）
M32 场景为白色背景页面（--bg-surface），phone-body 32px padding。不开 --card 的理由是「白底页面上圆角无意义」，而非此前写的"避免双重 padding"。cell-group__content 本身就是 `background: var(--bg-surface)`（白底），与白底页面融合，圆角收边无视觉意义。

### 决策 8：--card 开关通用规则（用户反馈提炼）
**开 --card 的充要条件：phone-body 横向 padding > 0 且页面背景为灰色（--bg-page）。** 灰底上白底内容需要圆角收边；白底页面（--bg-surface）圆角无意义；通栏 0px 无横向留白，圆角也无意义。这与 cell.json 第 134/163 行既有规则（"宿主层提供横向留白时开卡片修饰类"）一致，补充了"页面背景灰/白"维度。四档对应：M0 不开（0px）、M8 开（灰底+8px）、M16 开（灰底+16px）、M32 不开（白底）。

### 假设
- 场景 spec 里的 M1/M2 是"当前实现规格"而非"时间点决策快照"（archive 才是快照），故非 archive spec 需同步命名
- 现有场景消费 `var(--spacer-16)` 不受 Token 改名影响（spacer 体系不动）
- 无新场景需要立即应用 M8/M32 档位；本次只定义规则与 Token，不生成新场景
