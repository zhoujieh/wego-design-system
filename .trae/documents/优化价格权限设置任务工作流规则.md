# 优化"价格权限设置"任务暴露的工作流规则

## Summary

最近一次"价格权限设置"原型生成任务暴露 4 个工作流规则缺口:
1. app 图标没显示——`lib/icons/app-center/` 子目录的 SVG 没被递归复制
2. 移动端内容区域内间距被覆盖——任务级 `page.css` 偏离 `templates/page.css` 基线,业务样式作用域不严
3. 双击 `index.html` 后点击入口无反应——`full-screen-modal` 用 `fetch()` 加载本地片段,`file://` 协议下被 CORS 拦截
4. 权限设置入口应是二级入口——`leaf_level: 2` 已声明,但生成时二级入口与一级入口 DOM 平级,只有 `data-parent-entry` 数据标记,无视觉从属

本轮按 `wego-uxsystem-iterate/references/workflow-iteration.md` 的四段式(环节归属 → 场景类型识别 → 判断条件定义 → 决策动作落地)沉淀规则。**纯增量补充,不改模板基线文件,不改已有规则**,避免影响其他场景。

### 4 个问题的根因定位

#### 问题 1:app 图标没显示
- **现象**:任务文件夹 `lib/icons/app-center/` 下只有 `价格管理.svg`,但 `index.html` 引用了 `一键开团.svg`/`店铺装修.svg`/`收款码.svg`/`我的小店.svg`/`数据中心.svg`/`私域键盘.svg` 等多个 SVG
- **根因**:`library-consumption.json` 的 `copyFiles` 列了 `assets/icons/`,但 wego-ux 执行复制时只复制了根目录的 SVG(`checkbox-check.svg`/`radio-dot.svg`/`tab-*.svg`),没递归复制 `app-center/` 子目录
- **加剧因素**:`templates/host-shell.html` 的 fallback 脚本只在"模板预览模式"下把 `./lib/` 替换为 `../../wego-design/assets/`,复制到任务目录后没有这个 fallback

#### 问题 2:移动端内容区域内间距被覆盖
- **现象**:移动端打开后内容区域左右内间距消失
- **根因**:任务级 `css/page.css` 的 `.modal-overlay` 实现偏离 `templates/page.css` 基线——任务级用 `position: absolute; inset: 0; display: flex; flex-direction: column`,模板用 `position: fixed; inset: 0; max-width: 390px; margin-inline: auto`(无 display: flex)。任务级 page.css 还重复定义了 `body { background: var(--bg-page); }`,与 `host-shell.css` 的 `body[data-host-shell="true"]` 共存
- **规则缺口**:没有规则禁止任务级 page.css 偏离模板基线;`allowed_page_styles` 只约束"布局胶水和业务作用域",没明确"不得覆盖核心容器盒模型"

#### 问题 3:双击 index 后点击入口无反应
- **现象**:用户双击 `index.html`(file:// 协议)打开后,点击"价格权限设置"入口无反应
- **根因**:`price-permission.js` 的 `loadModalFragment()` 用 `fetch('./pages/price-permission-modal.html')` 加载片段。**`fetch()` 在 `file://` 协议下会被浏览器 CORS 策略拦截**,即使同目录文件也无法加载。fetch 失败后进入 `.catch(() => showToast('页面加载失败,请重试'))`,但此时 `modalRootElement` 仍为 null,`showToast` 内部 `modalRootElement.appendChild(toast)` 抛错,用户看不到任何反馈
- **规则缺口**:`wego-ux/SKILL.md` 的"full-screen-modal 实现要点"第 3 条明确要求用 `fetch()`,没有要求 file:// 协议兼容;`prototype-fidelity-standard` 场景类型的 covers 没有覆盖"file:// 协议双击预览能力"

#### 问题 4:权限设置入口应是二级入口
- **现象**:生成的 `index.html` 中,"价格权限设置"入口与"设置"一级入口 DOM 平级,都是 `.host-shell-list` 的直接子 `<button>`,只有 `data-parent-entry="设置"` 数据标记,无视觉从属(缩进/嵌套)
- **根因(主因在 wego-product 阶段)**:`page_spec.json` 的 `host_container` 虽然声明了 `leaf_level: 2`、`entry_label: "设置"`、`subentry_label: "价格权限设置"`,但这只是数据字段。`page_surfaces[host-entry]` 把"宿主「我的」Tab → 设置 → 价格权限设置入口"整个路径塞进**一个 information_block**,没有结构化拆分父子入口层级,也没有在 `purpose` 中说明"价格权限设置是设置的二级入口,需要视觉从属"。下游 wego-design/wego-ux 消费时,只看到 `leaf_level: 2` 这个数字,不知道父子入口如何在页面上表达层级关系,最终 wego-ux 把二级入口与一级入口 DOM 平级排列
- **规则缺口(按环节归属)**:
  - **wego-product 阶段(主因)**:`wego-product/SKILL.md` 的"宿主挂载路径"和"页面角色拆分"章节没有要求"当 `leaf_level > 1` 时,`page_surfaces[host-entry]` 必须明确声明父子入口层级关系";`host_container` 的 `entry_label`/`subentry_label`/`leaf_level` 只是数据字段,没有要求在 `page_surfaces` 中结构化表达
  - **wego-design 阶段(次因)**:`uikit-plan.json` 的 `hostShell.routeBinding` 只定义 `entryTypes: ["cell", "grid-entry"]`,没有二级入口的视觉变体规则;`fallbackPageBlueprints[mobile-host-entry].layoutRules` 没有定义二级入口缩进/嵌套规则
  - **wego-ux 阶段(次因)**:`wego-ux/SKILL.md` 的"固定宿主模板"章节只说 `entry_label`/`subentry_label`/`leaf_level` 是数据字段,没说"二级入口必须有视觉从属"
- **现有可复用资产**:
  - `cell.json` 的 `structurePatterns` 第 9 条定义了子级缩进结构(`.cell__backspace` + `.cell__backspace-icon`)
  - `cell.json` 的 `modifierClasses` 包含 `.cell--indent`
  - `uikit-plan.json` 的 `pagePatterns[biz-rule-config].leftGuidePattern` 定义了 `domPattern: "父项 .cell + 子项 .cell.cell--indent"`,`indentWidth: "24px"`——但只用于 biz-rule-config 范式内

### 改动 3:问题 3 — file:// 协议双击预览兼容

**环节归属**:primaryWorkflowStage=`wego-ux`,secondaryWorkflowStages=[]
**场景类型**:扩展已有 `prototype-fidelity-standard` 的 covers,新增"file:// 协议双击预览兼容性"
**判断条件**:原型必须支持 `file://` 协议双击打开,所有交互(含模态打开)不得依赖 `fetch()`/`XHR` 加载本地文件
**决策动作落地**:

#### 3.1 修改 `wego-ux/SKILL.md` 的"full-screen-modal 实现要点"第 3 条
把现有第 3 条:
> 触发打开时:`fetch()` 业务片段 → `DOMParser` 提取 fragment 根节点或页面内容区 → 插入 `#modal-overlay` → 移除 `hidden` → `requestAnimationFrame(() => { overlay.classList.add('modal-overlay--active') })`,两段式触发确保浏览器先绘制初始 `translateY(100%)` 再过渡

改为:
> 触发打开时,优先采用**内联方案**确保 `file://` 协议双击可用:
> - **方案 A(推荐)**:把模态片段直接内联到 `index.html` 的 `#modal-overlay` 内作为默认内容(含 `hidden` 属性),JS 只控制显隐和状态回填,不调用 `fetch()`
> - **方案 B**:把模态 markup 放在 `index.html` 的 `<template id="modal-template">` 标签内,JS 用 `content.cloneNode(true)` 插入 `#modal-overlay`
> - **禁止**:用 `fetch()`/`XHR` 加载 `pages/*.html` 本地片段——`file://` 协议下会被浏览器 CORS 策略拦截,即使同目录文件也无法加载
> - `pages/*.html` 仍可保留作为内容源(供 `http.server` 预览或后续迁移),但 `index.html` 的交互不得依赖它
> - 两段式触发:`#modal-overlay` 移除 `hidden` → `requestAnimationFrame(() => requestAnimationFrame(() => overlay.classList.add('modal-overlay--active')))` 确保浏览器先绘制初始 `translateY(100%)` 再过渡

#### 3.2 修改 `wego-ux/SKILL.md` 的"页面打开方式"表格下方
在"full-screen-modal 实现要点"章节前补充一段:
"**file:// 协议兼容性(必读)**:原型必须支持双击 `index.html`(即 `file://` 协议)直接预览,所有交互(含模态打开、push 跳转、状态持久化)不得依赖 `fetch()`/`XHR` 加载本地文件。`fetch()` 在 `file://` 协议下会被浏览器 CORS 策略拦截,即使同目录文件也无法加载。如需拆分内容,使用 `<template>` 标签或内联到 `index.html`。"

#### 3.3 修改 `wego-ux/SKILL.md` 的"生成前 checklist"
追加一条:
"- [ ] 原型支持 `file://` 协议双击打开,所有交互不依赖 `fetch()`/`XHR` 加载本地文件"

## Assumptions & Decisions

### 假设
1. `templates/host-shell.*`、`templates/page.css`、`templates/page-shell.html` 是稳定基线,本轮**不修改**
2. `cell.json` 的 `.cell--indent` 修饰类已可用于二级入口缩进(`uikit-plan.json` 的 `leftGuidePattern.domPattern` 已验证)
3. 4 个问题都能匹配到已有场景类型,无需新增类型(避免类型膨胀)
4. 任务产物 `价格权限设置/` 文件夹本轮**不直接修复**,只沉淀规则(用户要求"优化工作流里对应的规则")

### 关键决策

#### 决策 1:问题 3 采用内联方案(方案 A)而非 fetch 降级
- **选择**:把模态片段内联到 `index.html` 的 `#modal-overlay` 内
- **理由**:`file://` 协议下 `fetch()` 必然失败,降级方案仍需预置内联内容,不如直接内联;`pages/*.html` 仍可保留作为内容源供 `http.server` 预览
- **影响**:生成的 `index.html` 文件会变大,但保证了双击可用性

#### 决策 2:问题 4 主因归 wego-product,规则主体落 wego-product/SKILL.md
- **选择**:把问题 4 的规则主体落到 `wego-product/SKILL.md`(宿主挂载路径 + 页面角色拆分章节),`uikit-plan.json` 和 `wego-ux/SKILL.md` 只放执行引用
- **理由**:用户复盘指出"权限设置是设置的二级页面,这个在需求阶段应该是有明确要定义的"。现有 `page_spec` 把"设置 → 价格权限设置"整个路径塞进一个 `information_block`,没有结构化声明父子入口层级,导致下游无法知道这是父子关系。规则必须在需求阶段就要求结构化声明,不能只靠 `host_container.leaf_level` 数字让下游自行推断
- **影响**:`wego-product/SKILL.md` 新增"二级入口层级声明"规则;`uikit-plan.json` 的 `routeBinding.entryHierarchy` 改为"从 page_spec 读取"的执行规则;`wego-ux/SKILL.md` 改为"读取 page_surfaces 声明,无声明则回 wego-product 补齐"

#### 决策 3:问题 4 二级入口视觉表达采用 `.cell--indent`
- **选择**:二级入口 cell 用 `.cell--indent` 修饰类
- **理由**:`cell.json` 的 `modifierClasses` 包含 `.cell--indent`;`uikit-plan.json` 的 `leftGuidePattern.domPattern` 已用"父项 .cell + 子项 .cell.cell--indent"模式,`indentWidth: "24px"`;`.cell__backspace` 用于"无前导内容的子项",宿主入口 cell 通常没有前导内容,但 `.cell--indent` 是更轻量的缩进表达
- **影响**:二级入口视觉上缩进 24px,与父入口形成层级

#### 决策 4:不新增场景类型,只扩展已有类型的 covers
- **选择**:扩展 `host-shell-route-binding`、`uikit-to-production-transform`、`prototype-fidelity-standard` 三个已有类型
- **理由**:4 个问题都是已有类型覆盖范围内的延伸,新增类型会造成类型膨胀,违反 workflow-iteration.md 的"通用化验证"原则
- **影响**:`scenarioTypeRegistry.types[]` 的 covers 字段会变长,但类型数量不变

#### 决策 5:不改 `templates/` 基线文件
- **选择**:`templates/host-shell.*`、`templates/page.css`、`templates/page-shell.html` 不动
- **理由**:用户明确要求"不要改坏了这里另外的场景有坏了";模板基线是其他场景的稳定依赖,改动风险高
- **影响**:规则只落到 `wego-ux/SKILL.md`(执行规则)和 `uikit-plan.json`/`library-consumption.json`(契约/计划),模板基线保持不变
