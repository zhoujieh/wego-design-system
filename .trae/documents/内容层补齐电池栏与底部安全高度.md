# 内容层补齐电池栏与底部安全高度 · 实施计划

## 背景与目标

当前 PC 端用 app 容器包裹显示时：

- `host-shell.html`（App 宿主模板）有电池栏 `.phone-status` + 底部 Home 指示条 `.phone-indicator`，但 `.phone-status` 实现为 **in-flow flex 占位**（44px 高度），与 [specs/预览页脚手架规范.md](file:///Users/baobei/CODE/wego-design-system/.codex/skills/wego-design/specs/预览页脚手架规范.md) 第 56-91 行描述的"absolute 悬浮 + 内容自身留距"方案**有偏差**。
- `page-shell.html`（内容层模板）**完全没有** `.phone-status` 和 `.phone-indicator`，且 `page.css` 顶部注释与 `wego-ux/SKILL.md` checklist **明令禁止**引用 safe-area Token 和 `.phone-status / .phone-indicator`。导致内容层 PC 端预览时 navbar 直接顶到手机壳最上方、底部无 Home 指示条，与宿主页视觉不一致。

目标：
1. 让内容层模板的 PC 端预览与 app 宿主页一样带电池栏和底部安全高度，移动端同链接隐藏
2. 统一采用 spec 规范的"**透明背景不占位 + 内容区域预留间距**"方案（phone-status / phone-indicator 均 `position: absolute` 悬浮）
3. 同步修正 host-shell.css 的 in-flow flex 偏差，与 spec 规范对齐
4. 同步修订所有描述该规则的文档、组件契约、checklist、验收项

## 实施方案

核心策略：**用 CSS 变量重置联动所有 safe-area 样式**。`.phone-screen` 定义 `--safe-area-top / --safe-area-bottom` 模拟值，`@media (max-width:767px)` 内把这两个 Token 重置为 0，所有依赖它们的样式（navbar top、bottom-nav padding、page-body padding、host-shell-page padding）自动归零，无需逐个重置。

**执行顺序（重要）**：
1. 先改 preview 标记区（改动 1、2）→ 跑生成脚本重新生成 components.css（改动 3）
2. 同步组件契约描述（改动 4、5）→ 递增 metadata version（改动 6）
3. 再改模板与样式（改动 7、8、9）
4. 最后改规则文档（改动 10、11、12）
5. 跑守门脚本验证

components.css 是自动生成的聚合产物，**严禁手改**。navbar 和 bottom-nav 的 safe-area 让位必须通过改 preview 标记区 → 跑 `extract-components-css.mjs` 的路径实现。

## 假设与决策

1. **以 spec 规范的 absolute 悬浮方案为权威**（用户明确要求"透明背景不占位 + 内容预留间距"），host-shell.css 的 in-flow flex 偏差同步修正

5. **既有任务产物不回溯**：规则修改后，仅对新任务生效
6. **phone-status 内容固定为 "9:41" / "5G"**，与 host-shell 完全一致，不做参数化
