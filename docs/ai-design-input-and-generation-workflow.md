# AI 页面生成输入与保证边界

> 状态：用户已确认
>
> 适用范围：微购业务页面进入 `wego-design` 前的输入整理与生成边界
>
> 不包含：生成后的视觉评审、细粒度浏览器守卫和具体业务场景实现

## 1. 目标

微购页面可能只收到一段自然语言，也可能同时收到参考图、用户制作的线框图或高保真 Figma 设计稿。工作流不强制用户准备某一种视觉输入，也不再由系统生成线框图；所有已提供材料先按职责归类，再编译为同一份临时 `generation_packet`，最后才进入页面生成。

`generation_packet` 用于减少遗漏、冲突和实现阶段的临时自由发挥。它只能保证已明确约束得到执行，不能推断用户尚未表达的审美答案，也不能把“可生成”包装成“保证命中”。

## 2. 统一链路

```text
识别用户输入
  → wego-product 澄清并确认 prototype_brief
  → wego-design 按输入职责形成 generation_packet
  → 检查缺失、冲突与实现可达性
  → 读取必要 Preview、组件契约与 Token
  → 生成真实业务页面
```

`prototype_brief` 始终是业务事实的唯一权威。参考图、用户线框图和 Figma 只能约束其职责范围内的结构或视觉，不得新增页面、字段、状态、流程、文案和业务结果。

## 3. 输入职责

| 输入 | 编译结果 | 可以约束 | 不得承担 |
| --- | --- | --- | --- |
| 自然语言 | `business_contract` | 业务目标、范围、入口、关键路径、状态、数据与产品阶段明确的交互视觉要求 | 未表达的业务事实和正式实现规格 |
| 参考图 | `reference_profile` | 密度、留白、媒体占比、文字层级、表面倾向和视觉节奏 | 直接照搬业务布局、由图片补造业务内容、把参考方向声明为精确还原目标 |
| 用户线框图 | `structure_profile` | 区域顺序、父子关系、导航、滚动、首屏信息和显隐关系 | 颜色、字体、间距、组件变体等正式视觉规格 |
| 高保真 Figma | `design_source` | 指定 Frame 的结构、Auto Layout、尺寸、排版、样式和资源 | 覆盖已确认业务事实或绕过微购正式组件、Preview 与 Token |

系统不主动生成线框图或文本分镜。用户主动提供的线框图仍是合法结构输入；它必须先与已确认 `prototype_brief` 对照，冲突部分不能进入设计实现。

若图片用途不明确，必须先确认它是“参考方向”还是“需要还原的最终目标”。高保真 Figma 必须定位到具体页面 Frame；只有文件级链接时不能猜测目标节点。

## 4. generation_packet

`generation_packet` 是设计阶段的临时生成模型，不是新的业务 Schema、迭代状态或独立确认产物，不单独写入 `_iterations/`。它至少包含：

- `business_contract`：已确认简报中的业务事实与产品阶段交互视觉要求。
- `structure_contract`：优先来自高保真 Figma，其次来自用户线框图；没有结构输入时按业务任务和共享设计原则形成。
- `visual_contract`：优先来自高保真 Figma，其次来自参考图；没有视觉输入时使用微购设计原则、Token 和现有 App 视觉语言。
- `content_fixture`：实际文案长度、数据数量、可用图片与资产，禁止先按空壳布局再强塞真实内容。
- `component_plan`：页面结构确定后命中的正式组件、变体和 Preview DOM。
- `layout_contract`：语义区域、首屏预算、主滚动区、嵌套滚动、横滑、sticky/fixed 区域、间距归属和媒体比例。
- `forbidden_decisions`：生成阶段不得新增模块、改变业务路径、重排已锁定区域或发明组件的事项。

生成前必须确认所有业务内容已经进入区域结构，首屏预算成立，数据量与密度匹配，图片比例和文本行数有明确处理，组件与变体真实存在，且不同来源之间没有未处理冲突。

## 5. 权威顺序与冲突

```text
业务事实：prototype_brief
结构视觉：高保真 Figma > 用户线框图 > 参考图 > 微购系统基线
实现规格：设计决策原则、Preview、组件契约与 Token
```

- Figma、线框或参考图不得改变已确认的目标、范围、入口、路径、状态、数据和可见结果。
- 参考图只能提取明确的视觉特征，不能作为不相关业务布局的尺寸基线。
- 用户线框图只约束结构，不自动升级为正式视觉要求。
- 正式设计系统无法支持输入要求时，先明确冲突与可用回退；回退改变产品指令或可见结果时退回 `wego-product` 更新并重新确认简报。
- UI Kit 继续只用于参考明确页面范式如何组合正式能力，不是业务页面模板，也不因本流程改变职责。

## 6. 保证等级

| 输入条件 | 能够保证 | 不能保证 |
| --- | --- | --- |
| 只有自然语言 | 已确认业务范围和显式要求得到实现 | 最终视觉符合未表达的个人偏好 |
| 提供参考图 | 指定的视觉特征进入生成约束 | 适配新业务结构后仍等同用户脑中的唯一答案 |
| 提供用户线框图 | 结构与信息关系按确认内容实现 | 最终视觉风格和精致程度 |
| 提供高保真 Figma 最终稿 | 在业务和设计系统允许范围内还原指定设计 | 与正式设计系统冲突部分的完全一致 |

工作流只能提高约束一致性和生成稳定性。没有最终高保真目标时，任何生成结果仍包含设计裁决空间；守卫可以防止偏离显式合同，但不能证明结果等于用户未表达的审美目标。

## 7. 当前实施边界

- 产品阶段只展示并确认文字版 `prototype_brief`，保留提交快照、范围哈希、失效和重新确认机制。
- 设计阶段在实现前形成临时 `generation_packet`，不新增持久化字段或第二次业务确认状态。
- 本阶段不修改 UI Kit 定位，不实现视觉评审 Agent，不扩展生成后细粒度视觉守卫，也不迁移已有业务场景。
