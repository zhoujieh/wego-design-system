## Clarifications

### Session 2026-07-13

- Q: 加价金额与加价比例的输入模式？ → A: 数字键盘顶部有"按金额"/"按比例"切换 Tab，默认按金额；点击快捷加价标签不拉起数字键盘，仅"手动输入"拉起数字键盘
- Q: 单一价格场景下输入框与数字键盘的关系？ → A: 点击输入框拉起数字键盘（键盘上方显示价格类型及当前价格，无金额/比例 Tab，直接修改售价）；"手动输入"拉起的数字键盘有金额/比例 Tab（修改加价方式）
- Q: 售价下限校验？ → A: 按金额加价时自动转换为比例，统一限制在 1%-300% 范围内；超出范围时 toast 提示并阻止保存
- Q: 输入框直接改售价时的校验联动与精度？ → A: 输入框改售价同样执行金额转比例校验（1%-300%）；售价精度 2 位小数

### Session 2026-07-25（价格计算规则定稿 — 可验证表格）

> 本次澄清源自实现期反复踩坑（售价错算、rate 单位错、区间佣金丢失）。以下表格是**业务真相来源**，实现时逐行验证，不得偏离。

**核心规则**：

- 赚佣金模式售价 = **供货价 + profit**（不是原始供货价）
- `rate` 字段是**小数**（0.3 = 30%），计算时 `profit = rate × 供货价`，不做 `/100`
- 区间价（`max > mini`）时 profit 有两个值，佣金显示为区间

**输入输出对照表（= 单元测试用例）**：

| 模式   | amountType | 输入                          | profit（赚多少） | 我的售价     |
| ---- | ---------- | --------------------------- | ----------- | -------- |
| 固定佣金 | 1（金额）      | value=30, mini=100          | 30          | 130      |
| 固定佣金 | 2（比例）      | rate=0.3, mini=100          | 30          | 130      |
| 固定佣金 | 2（比例）      | rate=0.3, mini=100, max=200 | 30\~60      | 130\~230 |
| 自由加价 | 1（金额）      | value=20, mini=100          | 20          | 120      |
| 自由加价 | 2（比例）      | rate=0.2, mini=100          | 20          | 120      |
| 自由加价 | 2（比例）      | rate=0.2, mini=100, max=200 | 20\~40      | 120\~140 |

**显示规则**：

- `¥` 符号由 UI 统一添加，ViewModel 只返回纯数字字符串
- 价格/佣金整数不显示小数点（`100` 不是 `100.0`）
- 区间价格式：`100~200`（中间用 `~`）

## 用户场景与测试 *（必填）*

### 用户故事 1 - 初次帮卖时设置售价（优先级：P1）

> Figma: fileId=`Z4iltAbicAYQMEWhyAWjE0` | 默认态 `7195:76529` | 编辑售价 `7197:10920` | 手动输入 `7197:12233`

仅当供应商设置的帮卖方式为"自由定价"时，代理商从供应商店铺挑选商品并点击【立即帮卖】后，系统根据供应商设置的加价规则自动计算"我的售价"并显示对应佣金。单一价格时显示输入框可直接填写售价；区间价格时不显示输入框，仅展示价格区间和佣金区间。代理商可以通过快捷选项（如 +30%、+20%）或点击"手动输入"拉起数字键盘来设置加价金额或比例。系统自动根据供货价计算佣金。点击【帮卖并分享】，即帮卖商品到自己的店铺，并保存供货价、佣金信息。

例如：代理商小王在供应商老刘的店铺发现一款运动鞋，供货价 100 元，帮卖方式为自由定价。小王点击【立即帮卖】，系统默认按供应商设置的加价金额加 100 元，售价 200 元，佣金 100 元。小王觉得佣金太高，通过快捷标签或手动输入拉起数字键盘，将售价改为 150 元，佣金变为 50 元，点击【帮卖并分享】完成帮卖。

**为何此优先级**：这是帮卖商品的核心入口流程，没有它代理商无法设置售价和佣金，整个帮卖功能无法运作。

**独立测试**：在供应商店铺中找到帮卖方式为自由定价的商品，点击【立即帮卖】，验证弹窗展示、价格计算、快捷选项/手动输入键盘、佣金自动计算和帮卖并分享全流程。

**验收场景**：

1. **给定** 供应商商品供货价为 100 元、帮卖方式为自由定价、单一价格、默认加价金额为 100 元，**当** 代理商点击【立即帮卖】，**那么** 弹窗显示输入框（默认售价 200 元）、佣金 100 元，且输入框下方显示默认加价金额/比例及 +30%、+20% 快捷选项和"手动输入"文字链
2. **给定** 弹窗已展示，**当** 代理商点击输入框，**那么** 拉起数字键盘（上方显示价格类型及当前售价 200 元，无金额/比例 Tab），可直接修改售价，佣金随售价实时重算
3. **给定** 弹窗已展示默认售价 200 元，**当** 代理商点击 +20% 快捷标签，**那么** 直接按供货价上浮 20% 重新计算售价并显示，佣金同步更新，不拉起数字键盘
4. **给定** 弹窗已展示，**当** 代理商点击"手动输入"拉起数字键盘（默认"按金额"Tab），输入加价金额 50 元，**那么** 售价更新为 150 元，系统自动计算佣金显示 50 元
5. **给定** 数字键盘已拉起，**当** 代理商切换到"按比例"Tab 并输入 50%，**那么** 售价按供货价上浮 50% 重新计算，佣金同步更新
6. **给定** 代理商已设置合法售价，**当** 点击【帮卖并分享】，**那么** 帮卖商品到自己的店铺并保存供货价、佣金信息

### 用户故事 2 - 编辑已有帮卖商品（优先级：P1）

代理商帮卖商品一段时间后，想调整售价。在自己的店铺找到对应帮卖商品，点击【编辑】，调用本组件。不管帮卖方式是"固定佣金"还是"自由定价"，都调用该组件：

- **固定佣金**：弹窗标题为"赚佣金"，页面直接显示我的售价和佣金金额，不能修改
- **自由定价**：弹窗标题为"加价卖"，数据为上一次保存的值；单一价格显示输入框可直接填写售价，区间价格不显示输入框仅展示区间；点击快捷加价标签或【手动输入】拉起数字键盘修改加价金额或比例；系统自动根据供货价计算佣金

例如：代理商小王帮卖的运动鞋售价 150 元、佣金 50 元（自由定价），粉丝觉得价格太高。小王找到该商品点击【编辑】，弹窗标题为"加价卖"，回显上次保存的售价 150 元和佣金 50 元，小王通过快捷标签修改售价为 119 元，佣金变为 19 元，点击【保存】保存供货价和佣金信息。

**为何此优先级**：代理商需要灵活调整售价以应对市场反馈，这是帮卖业务持续运营的必要能力。

**独立测试**：在代理商自己的店铺中分别找到自由定价和固定佣金的已帮卖商品，点击【编辑】，验证弹窗标题、数据回显、可编辑性差异和保存/分享全流程。

**验收场景**：

1. **给定** 代理商有一个自由定价、单一价格的帮卖商品（上次保存售价 150 元、佣金 50 元），**当** 代理商点击【编辑】，**那么** 弹窗标题为"加价卖"，显示输入框（回显售价 150 元）和佣金 50 元
2. **给定** 代理商有一个固定佣金的帮卖商品，**当** 代理商点击【编辑】，**那么** 弹窗标题为"赚佣金"，页面显示我的售价和佣金金额，且不能修改

### 用户故事 4 - 直播间来源帮卖（优先级：P2）

### 用户故事 5 - 价格隐藏与异常处理（优先级：P2）

当供应商的价格被隐藏导致无法帮卖时，系统根据隐藏范围弹出不同的模态框引导代理商处理。批发价隐藏时可直接在弹窗内确认公开，不跳转外部页面；所有价格隐藏时引导前往价格管理设置页。

**为何此优先级**：价格隐藏是供应商隐私管控的常见场景，需要优雅引导代理商处理，避免帮卖流程中断。

**独立测试**：构造批发价隐藏和所有价格隐藏两种场景，验证模态框内容、确认行为和 toast 提示。

**验收场景**：

1. **给定** 供应商代理售价为批发价且设置了起购量、代理商批发价隐藏，**当** 代理商打开帮卖弹窗，**那么** 弹窗内弹出模态框（标题"批发价被隐藏不支持帮卖"，内容"确认后，将自动公开批发价支持帮卖"）
2. **给定** 批发价隐藏模态框已展示，**当** 代理商点击【确认】，**那么** 直接公开批发价，toast 提示"批发价已设置为公开"，弹窗关闭
3. **给定** 接口返回所有价格隐藏错误，**当** 系统检测到该错误，**那么** 弹出模态框（内容"你店铺所有价格被隐藏，不支持帮卖，请前往价格管理设置"），确认后跳转至价格设置页

### 边界场景

> Figma 异常态参考: 加载中 `7207:2473` | 加载失败 `7207:23598` | 批发价隐藏 `7207:24420` | 所有价格隐藏 `7207:24264`

- **当** 加价比例低于 1% 时，**那么** toast 提示"佣金比例不能小于 1%"，阻止保存
- **当** 加价比例高于 300% 时，**那么** toast 提示"佣金比例不能大于 300%"，阻止保存
- **当** 加价比例已输入 2 位小数，**那么** 数字键盘输入层静默拦截第 3 位小数（无 toast）
- **当** 供应商在代理商帮卖后修改了可加价金额/比例，**那么** 代理商的加价金额保持不变
- **当** 供应商在代理商帮卖后修改了供货价，**那么** 代理商的供货价自动更新为最新值，加价金额不变
- **当** 商品已不能帮卖（供应商隐藏供货价、删除价格、删除商品、下架商品），**那么** 后端自动删除该帮卖商品；本组件收到非 0 errcode 时仅 toast 提示，不主动删除
- **当** 商品已不能帮卖且代理商已进入赚佣金页面，**当** 点击保存，**那么** 后端返回错误，组件 toast 提示"该商品不支持帮卖"
- **当** 供应商设置了多个价格类型，**那么** 后端按其设置模式预选生效供货价并通过接口下发，组件直接使用
- **当** 代理商批发价隐藏且代理售价为批发价（含起购量/销售单位），**那么** 弹窗内弹出确认模态框，确认后直接公开批发价
- **当** 所有价格被隐藏（接口错误码 11001409），**那么** 弹出模态框引导前往价格管理设置
- **当** 弹窗从直播间打开（来源=live），**那么** 遮罩可关闭、底部按钮调整、不显示佣金保密提示
- **当** 保存接口返回失败（网络超时、服务端错误），**那么** 弹窗保持打开，保留已设数据，toast 提示失败，可重试
- **当** 获取帮卖信息接口请求中，**那么** 弹窗内容区显示 loading 状态
- **当** 获取帮卖信息接口返回失败，**那么** 内容区显示失败提示（含"重试"和"关闭"按钮）
- **当** 键盘已打开，**那么** 关闭键盘的途径仅限三种：①点击加价标签（同时应用加价）②点击"手动输入"（同时切换为手动输入模式，键盘不关）③点击"确定"（校验通过后应用新值）；点击弹窗空白区域**不关闭**键盘（见 Session 2026-07-27）
- **当** 代理商点击数字键盘的数字/小数点/退格按钮，**那么** 按钮显示按压态视觉反馈（点击效果）；连续点击数字追加到输入末尾，小数点不可重复输入，退格删除末位（未显式定义的交互均参考普通数字键盘输入习惯）

### 功能需求

- **FR-001**：仅当帮卖方式为"自由定价"时，代理商初次帮卖**才调用**本组件

  **边界**：
  1. 加载中：不适用（纯路由判定，无数据加载）
  2. 加载失败：不适用（路由判定不发起请求）
  3. 空数据：不适用（无数据展示）
  4. 边界值：帮卖方式字段为 null 或非"自由定价"/"固定佣金"枚举值 → 不调用本组件（走其他流程）
  5. 权限：不适用（路由层不判断权限，权限由 FR-041 在接口层处理）
  6. 并发：不适用（无并发操作）
  7. 异步时序：不适用（纯同步路由判定）
- **FR-002**：系统**必须**根据供应商设置的加价金额/比例自动计算默认售价，并显示对应佣金

  **边界**：
  1. 加载中：走 FR-031 loading 状态（接口未返回前不计算默认售价）
  2. 加载失败：走 FR-031 失败提示+重试（无数据则不计算）
  3. 空数据：供应商未设置加价（`distributionConfig` 缺失）→ 走 FR-004 兜底值（30%>20%>10%）作为默认加价
  4. 边界值：rate 字段单位为小数（0.3=30%，非整数 30，见 Bug-05/Bug-06 回归 case：`freeAddPriceRate=0.3` 应算出 profit=30，而非 0.3）；金额/比例两种 amountType 都要支持
  5. 权限：不适用（权限由 FR-041 处理）
  6. 并发：不适用（默认值计算无用户交互）
  7. 异步时序：不适用（数据返回后同步计算）
- **FR-003**：系统**必须**自动根据供应商的供货价计算佣金

  **边界**：
  1. 加载中：走 FR-031 loading 状态
  2. 加载失败：走 FR-031 失败提示+重试
  3. 空数据：供货价缺失/被隐藏 → 走价格隐藏模态框（FR-027 所有价格隐藏 / FR-028 批发价隐藏），不计算佣金
  4. 边界值：区间价（`max > mini`）时 profit 有两个值，佣金显示为区间；区间两端相等时（`profits[0]==profits[1]`）应显示单一值非 `100~100`（见 Bug-03 回归 case：mini=100,max=100,rate=0.3 → 显示"30"非"30\~30"）；按金额加价区间价不能退化为单一价（见 Bug-02 回归 case：mini=100,max=200,amount=50 → profit=\[50,50]→售价区间\[150,250]）
  5. 权限：不适用
  6. 并发：不适用
  7. 异步时序：不适用（同步计算）
- **FR-004**：系统**必须常驻显示**快捷加价区域，不依赖用户交互触发。快捷加价标签最多 3 个（去重后），另加 1 个"手动输入"文字链。标签候选优先级（按顺序去重后取前 3）：
  1. **代理/供应商当前加价**：`myItem=true`（编辑场景）取代理商当前保存加价（合并 `distributionConfig + distributionAgentPrices[0]`）；`myItem=false`（初次帮卖）取供应商设置加价（`distributionConfig`）
  2. **店铺设置加价**（`itemPriceConfig`）：`itemPriceType=0`→按金额 `itemPriceAdd` 元；`itemPriceType=1`→按比例 `itemPriceAdd%`（即 `itemPriceAdd/100` 小数）
  3. **前端缓存自定义加价**（localStorage `custom_add_price`，spec FR-024）
  4. **兜底值**（仅当前 3 个不足时补齐，按优先级 30% > 20% > 10%）
     去重规则：相同 `amountType + value` 视为重复，跳过排序靠后的。单位约定见下方「价格/加价字段单位表」。
  **边界**：
  1. 加载中：走 FR-031 loading 状态（加载期间不显示快捷加价区域或显示骨架）
  2. 加载失败：走 FR-031 失败提示+重试（不显示快捷加价区域）
  3. 空数据：所有候选源（代理/供应商当前加价、店铺设置 `itemPriceConfig`、前端缓存）均缺失 → 用兜底值 \[0.3, 0.2, 0.1]（小数）补齐到 3 个标签
  4. 边界值：候选去重后不足 3 个 → 用兜底值补齐；`itemPriceAdd` 单位随 `itemPriceType` 变化（`itemPriceType=0` 为元整数，`itemPriceType=1` 为百分比整数 30=30%，需 `/100` 转小数，见「价格/加价字段单位表」）；`QuickAddPriceTag.value` 在 `amountType=2` 时必须存小数 0.3 而非整数 30（Bug-05/Bug-06 回归 case：点击兜底 +30% 标签，佣金不能放大 100 倍）
  5. 权限：不适用
  6. 并发：不适用（标签为静态展示，无并发）
  7. 异步时序：不适用
- **FR-005**：点击"手动输入"时**必须**拉起数字键盘，键盘顶部有"按金额"/"按比例"切换 Tab，默认按金额；切换后实时重算售价和佣金

  **边界**：
  1. 加载中：不适用（用户主动点击触发，加载已完成）
  2. 加载失败：不适用
  3. 空数据：不适用
  4. 边界值：切换 Tab 后实时重算，金额/比例互转时单位必须正确（金额→比例 ÷供货价×100，比例→金额 ×供货价÷100，见 Bug-05/Bug-06 回归 case）
  5. 权限：不适用
  6. 并发：快速来回切换 Tab → 以最后一次切换为准（Tab 状态用 observable 驱动，避免中间态残留）
  7. 异步时序：不适用（同步切换）
- **FR-005a**：点击快捷加价标签（如 +30%、+20%）时**直接应用**对应加价比例并重算售价和佣金，**不拉起**数字键盘

  **边界**：
  1. 加载中：不适用（用户主动点击触发）
  2. 加载失败：不适用
  3. 空数据：不适用
  4. 边界值：点击标签后高亮规则按 `amountType + value` 精确匹配（不做金额↔比例转换，见 Session 2026-07-28）；`amountType=2` 时 value 为小数 0.3，UI 显示 "+30%"（Bug-05/Bug-06 回归 case）
  5. 权限：不适用
  6. 并发：快速连点不同标签 → 以最后一次点击为准（observable 驱动重算）
  7. 异步时序：不适用
- **FR-006**：代理商的售价**必须**在供应商供货价基础上加价计算

  **边界**：
  1. 加载中：走 FR-031 loading 状态
  2. 加载失败：走 FR-031 失败提示+重试
  3. 空数据：供货价缺失 → 走 FR-027/FR-028 价格隐藏处理
  4. 边界值：售价 = 供货价 + profit（不是原始供货价，见 Session 2026-07-25 核心规则）；区间价时售价也是区间（Bug-02 回归 case：不能退化为单一价）
  5. 权限：不适用
  6. 并发：不适用
  7. 异步时序：不适用
- **FR-007**：加价额度和比例默认取供应商设置，**必须**支持代理商修改

  **边界**：
  1. 加载中：走 FR-031 loading 状态（默认值未拿到前不可修改）
  2. 加载失败：走 FR-031 失败提示+重试
  3. 空数据：供应商未设置加价 → 用兜底值（FR-004）作为默认，用户仍可修改
  4. 边界值：修改后的值必须过 FR-008（1%-300%）和 FR-009（2 位小数）校验
  5. 权限：不适用
  6. 并发：不适用（用户单次操作）
  7. 异步时序：不适用
- **FR-008**：加价比例**必须**限制在 1%-300% 范围内；当代理商按金额加价时，系统**必须**自动将金额转换为比例并执行同一校验，超出范围时 toast 提示并阻止保存

  **边界**：
  1. 加载中：不适用（用户输入时已加载完成）
  2. 加载失败：不适用（本地校验）
  3. 空数据：不适用
  4. 边界值：`rate=0.01`（1%）和 `rate=3.0`（300%）为合法边界，通过校验；`rate=0.009`（<1%）→ toast"佣金比例不能小于 1%"阻止保存；`rate=3.01`（>300%）→ toast"佣金比例不能大于 300%"阻止保存；按金额加价时金额转比例 = 加价金额 ÷ 供货价（Bug-05 回归 case：`validateRate` 入参用百分比整数 30.0=30%，调用前 `rate × 100` 转换，不能拿小数 0.3 直接和 1 比较）；输入框直接改售价时售价转比例 = (售价-供货价) ÷ 供货价，执行同一校验
  5. 权限：不适用
  6. 并发：不适用（校验为同步）
  7. 异步时序：不适用
- **FR-009**：加价比例**必须**支持 2 位小数，第 3 位小数输入**必须在数字键盘输入层实时阻止**（静默拦截，无 toast）；`AddPriceValidator` 仅负责 1%-300% 范围校验，不重复做精度限制

  **边界**：
  1. 加载中：不适用（用户输入时触发）
  2. 加载失败：不适用
  3. 空数据：不适用
  4. 边界值：已输入 "0.30" 后再按 "5" → 静默拦截不追加（无 toast）；已输入 "0.3" 后按 "0" → 允许（变成 "0.30"）；小数点不可重复输入；售价精度同样 2 位小数（FR-010）；`AddPriceValidator` 只管 1%-300%，不重复限制精度（Session 2026-07-16）

#### 加价比例输入校验

- **比例范围**：1% ≤ 加价比例 ≤ 300%
- **金额转比例**：按金额加价时，系统自动将加价金额 ÷ 供货价转换为比例，执行同一 1%-300% 校验
- **输入框售价校验**：通过输入框直接修改售价时，系统自动将（售价 - 供货价）÷ 供货价 转换为比例，执行同一 1%-300% 校验
- **售价精度**：售价最多 2 位小数，第 3 位小数输入被阻止
- **超下限**：toast 提示"佣金比例不能小于 1%"，阻止保存
- **超上限**：toast 提示"佣金比例不能大于 300%"，阻止保存
- **精度限制**：最多 2 位小数，已输入 2 位小数后第 3 位输入被阻止

#### 商品不可帮卖状态流转

**触发条件**（满足任一即不可帮卖）：

- 供应商隐藏供货价
- 供应商删除商品价格
- 供应商删除商品
- 供应商下架商品

**异常处理**：

- 未进入编辑页：自动删除帮卖商品
- 已进入赚佣金页面并点击保存：提示"该商品不支持帮卖"

#### 快捷加价标签组合与缓存规则

- **常驻显示**：自由加价模式下快捷加价区域始终显示，不依赖用户交互触发
- **标签优先级**：第 1 个 = 当前保存的代理商设置的加价（优先级 Ⅰ）> 供应商设置的加价（优先级 Ⅱ）；第 2 个 = 兜底值（按优先级 30% > 20% > 10%）；第 3 个 = 前端缓存的自定义加价金额/比例
- **去重**：与已有标签重复时不替换
- **手动输入后更新**：代理商通过"手动输入"确认新加价后，快捷标签替换为手动输入的值，并缓存到本地供后续打开时使用
- **缓存生命周期**：本地持久化，除非用户清除应用数据

**字段业务含义**：

- `供货价` —— 供应商设定的商品出货价格，代理商售价的基础
- `加价金额` —— 代理商在供货价基础上增加的绝对金额，决定佣金大小
- `加价比例` —— 代理商在供货价基础上增加的百分比（1%-300%），决定佣金大小
- `我的售价` —— 供货价 + 加价金额，即代理商面向消费者的最终售价
- `佣金` —— 代理商每售出一单的收益，等于加价金额
- `帮卖方式` —— 供应商设定的分销模式（自由定价 / 固定佣金），决定弹窗标题和可编辑内容
- `生效供货价` —— 根据供应商设置（最高可见价 / 最低可见价 / 指定价格类型）确定的用于计算代理商售价的基础供货价
- `价格类型` —— 供应商设定的价格分类（如批发价、零售价等），影响数字键盘显示和生效供货价取值
- `弹窗来源` —— 标识弹窗打开场景（普通 / 直播间），决定遮罩行为和底部按钮配置
- `店铺自动加价配置`（`itemPriceConfig`）—— 店铺级默认加价规则，作为快捷加价标签的第 2 候选来源；`itemPriceType=0` 表示按金额加价（`itemPriceAdd` 单位为元），`itemPriceType=1` 表示按比例加价（`itemPriceAdd` 单位为百分比整数，如 30 表示 30%）
- `myItem`（接口 result）—— 是否为代理商已帮卖商品；`true`=编辑场景（双按钮【保存】+【分享】），`false`=初次帮卖（单按钮【帮卖并分享】）。**跨模式按钮判定字段**，不依赖 `distributionType`。

### 价格 / 加价字段单位表（强制，写代码前必读）

> 历史教训：本节未定义前，`QuickAddPriceTag.value` 在 `amountType=2`（按比例）时被实现为百分比整数（30.0），与 `freeAddPriceRate` 的小数（0.3）混存，导致点击兜底 +30% 时佣金放大 100 倍。**单位必须在 spec 锁定，实现/测试一律遵守**。

| 字段 / 变量                                   | 类型            | 单位（amountType=1 按金额） | 单位（amountType=2 按比例）      | 示例            |
| ----------------------------------------- | ------------- | -------------------- | ------------------------- | ------------- |
| `freeAddPriceValue`（接口/DTO）               | Double        | 金额绝对值（元）             | 不使用（默认 0）                 | 30.0 = 加 30 元 |
| `freeAddPriceRate`（接口/DTO）                | Double        | 不使用（默认 0）            | **小数**（0.3 = 30%）         | 0.3 = 30%     |
| `fixedRebateValue` / `fixedRebateRate`    | Double        | 同上                   | 同上（小数）                    | —             |
| `itemPriceAdd`（接口 `itemPriceConfig`）      | Int           | 元（金额整数）              | **百分比整数**（30 = 30%）       | 30            |
| `QuickAddPriceTag.value`（前端模型）            | Double        | 金额绝对值（元）             | **小数**（0.3 = 30%）         | 30.0 / 0.3    |
| `AgentResaleCache.custom_add_price.value` | Double        | 金额绝对值                | **小数**（0.3 = 30%）         | 30.0 / 0.3    |
| `currentAddPriceAmount`（ViewModel）        | Double        | 金额绝对值（元）             | 不使用                       | 30.0          |
| `currentAddPriceRate`（ViewModel）          | Double        | 不使用                  | **小数**（0.3 = 30%）         | 0.3           |
| `FALLBACK_RATES`（兜底常量）                    | List\<Double> | —                    | **小数**：\[0.3, 0.2, 0.1]   | 0.3 = 30%     |
| `MIN_RATE` / `MAX_RATE`（校验）               | Double        | —                    | **百分比整数**：1.0 / 300.0     | 30.0 = 30%    |
| UI 标签文案                                   | String        | 「+30元」               | 「+30%」（显示时 `value * 100`） | —             |

**铁律**：

- 任何 `*Rate` 字段在 ViewModel/缓存/DTO 层一律小数（0.3 = 30%）
- 任何百分比校验（如 `AddPriceValidator`）入参用百分比整数（30.0 = 30%），调用前必须 `rate * 100` 转换
- UI 渲染时若 amountType=2，文案显示 `value * 100` + `%`；金额直接显示 `value` + `元`
- 单位不明确时**必须追问后端或查 Apifox**，禁止猜（project\_rules「SDK 准确性」红线）

### 关键实体 *（若涉及数据则填写）*

- **供应商商品**：供货方提供的原始商品，包含一个或多个 SKU，每个 SKU 有供货价；供应商设定帮卖方式和可加价金额/比例
- **帮卖商品**：代理商基于供应商商品创建的分销商品，包含代理商设定的加价金额/比例、计算出的售价和佣金
- **加价配置**：代理商对某个帮卖商品的售价设置，包含加价金额、加价比例、对应的售价和佣金，可多次编辑修改
