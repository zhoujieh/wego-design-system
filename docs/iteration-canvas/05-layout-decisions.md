# 迭代画布 · 排版决策记录（Layout Decisions）

> 用途：预研期把"画布真实输出怎么排才符合验收"的每一个关键决定固化下来，作为后续通用技能（wego-sdd-spec / 画布生成技能）的排版规则来源。
> 维护方式：一条决策一行，固定五栏；**状态只允许 `已验证`（浏览器真实视口实测）/ `待验证`（已实现未实测）/ `已否决`（试过不用，并记原因）**。每条都要能追溯到一次具体实现或走查，不写未经验证的设想。
> 最近更新：2026-09-04（PR #172，第一条「发布产品」链路做透：cell 状态矩阵、裁剪窗与布局分离、平铺渲染补私有样式、繁简通用规则）

## 一、整体信息架构（自上而下）

| 场景问题 | 怎么定 | 为什么 | 适用边界 | 状态 |
| --- | --- | --- | --- | --- |
| 一张画布先放什么、后放什么 | 顺序固定：①迭代头卡（标题/状态/ID/目标/元信息）→ ②范围卡（纳入 in-scope / 不纳入 out-of-scope 双列）→ ③入口卡（从哪些入口进）→ ④**UI 缺口清单卡**（有缺口才出现）→ ⑤按流程链（flow）逐条纵向堆叠 | 与 spec 的"范围→入口→流程→状态"结构同构，开发 AI 从上到下读就是需求本身；缺口清单前置，避免缺口散落在各流程里被漏掉 | 一个迭代一张画布；跨迭代对比不走此结构 | 已验证 |
| 纳入/不纳入范围怎么区分 | 双列，纳入列绿点、不纳入列琥珀点 | 颜色语义与状态色 Token 一致（success/warning），不额外造色 | 仅表达范围归属，不表达优先级 | 已验证 |
| 流程之间怎么排 | 流程块**纵向**堆叠（每个 flow 一张白卡，大间距分隔）；一条流程内部 `.flow-chain` 用**纵向 column**：连续的里程碑整页节点按"连续段"包成一行**横向**排列（段内右箭头承接），**cell 状态矩阵节点纵向独占整行**（不与整页节点挤同一行），段与段之间插一个**向下承接箭头**（右箭头图标 rotate 90°） | 纵向=步骤推进，横向=同一层级并列；矩阵节点宽达 1560，若用 flex-wrap 会和后续整页节点挤在同行剩余空间造成错位与大片空白，故确定性分段：整页段横排、矩阵独占、向下箭头明确阅读走向 | 连续段内整页节点数按一行放得下为准（393/块）；矩阵永远独占一行；简单流程可只有一个连续段、无矩阵、无向下箭头 | 已验证（第一条链实测） |
| 一条流程节点头要带什么 | P1/P0 优先级徽标 + 流程标题 + 一句描述 | 开发先看主动线（P1），描述交代这条链在验证什么 | P1 用品牌绿浅底，其余中性 | 已验证 |

## 二、三类状态块（核心）

| 场景问题 | 怎么定 | 为什么 | 适用边界 | 状态 |
| --- | --- | --- | --- | --- |
| 一个"状态"在画布上用什么承载 | 三类：**整页状态块** / **局部状态块** / **规格占位卡**，视觉上用小徽标区分（局部=信息蓝"局部"，缺口=琥珀"缺口"，整页无徽标） | 整页看上下文、局部聚焦字段、缺UI不伪造——三种信息密度需求不同，不能用一种块硬撑 | 三类互斥，一个状态块只属于一类 | 已验证 |
| 整页状态块尺寸 | 默认视口 iPhone 15 Pro：**393 × 852**，真实场景 DOM 全量渲染；高度可拖拽调整 | 与真机视口一致，开发能看到完整上下文；长表单可拖高 | 宽固定 393（设备宽度不是设计 Token，允许像素值）；高默认 852、可拖 | 已验证 |
| 局部状态块怎么来 | **整页渲染 → prepare 驱动到目标状态 → clip 只裁剪聚焦目标**，clip 本身不产生状态；块高=目标元素高+2×pad，蓝描边 | 复用同一套真实渲染，保证局部与整页一致、不会出现"局部是另一套假 UI"；裁剪是纯视图动作 | 适合"只关心某字段组/某单行"的状态（如价格区、某入口行）；需要跨区域看联动时仍用整页块 | 已验证 |
| clip 目标怎么声明 | 编排数据里给 `{selector, closest, pad}`：selector 锚点（优先 data-form-field 等稳定钩子）、closest 上提到要展示的容器、pad 默认 10 | selector 只锚一个元素，closest 决定"聚焦多大范围"，两者解耦 | selector 必须是业务场景里稳定存在的钩子；找不到时**显性红虚线告警**（clip-miss），禁止静默留白 | 已验证 |
| **局部块裁剪的关键坑：目标在业务页内部滚动容器里** | 不能只移外层/裁 host：必须先让目标在**每一层内部纵向滚动祖先**（如 `.layout-scroll`）里滚到可视顶（只设 scrollTop、scrollLeft 锁 0），再上移场景根对齐、最后裁 host 高 | 内部滚动容器有自己的 overflow 裁剪，外层位移穿不透它；`scrollIntoView` 会引入横向偏移并带动外层画布，故改为手动只设纵向 scrollTop | 通用算法，不绑定具体业务；嵌套多个滚动容器时从外到内逐层设置 | 已验证 |
| **局部块裁剪的决定性坑（弹窗类）：裁矮宿主会令内部重排错位** | **裁剪与布局分离**：`.scene-host` 恒保持完整设备高度 852（内部弹窗贴底/内部滚动布局永不因裁剪变化），局部块在宿主外再包一层 `.frame-clip` 裁剪窗（overflow:hidden，高度=目标高+2pad），只移动宿主内场景根 translateY 对齐、由裁剪窗裁出目标区域；局部块不再输出"拖拽调高度"把手 | 发布表单是 fixed 遮罩 + **贴底**弹层卡片 + `.modal__body` 内部滚动；一旦把 host 从 852 裁矮到 72，弹层卡片会重新贴底居中、内部滚动容器被压扁，按裁矮前坐标算的 translateY 全部失准——表现为"input 明明有值、字段 label 却被移出裁剪窗"。让宿主布局恒定、只让外层窗负责裁切，普通页与弹窗页都稳定，且天然幂等无需"恢复高度" | 仅局部块包 frame-clip；整页块宿主直接摆放、保留拖拽把手 | 已验证（G1–G7 共 38 局部块逐块复看，label/值/标签/开关均正确落位） |
| 局部块测量的收敛时点 | "复位场景根 transform → 滚内部滚动祖先 → rect 算位移 → translateY + 设裁剪窗高"，并在双 rAF、160ms、420ms 多次重算 | 业务 init/字体/晚到图片可能改变几何，多时点重算兜底；宿主恒高后不再有"裁矮污染测量"的自锁问题 | 图片类晚到内容若改变目标高度，仍可能需要追加一次重算 | 已验证 |
| 规格占位卡长什么样 | 393 宽、虚线琥珀边框、浅琥珀底；居中放：感叹号圆点 + "规格已声明·待业务场景补充 UI"徽章 + spec 引用（如 `states.field-validation`）+ 一句说明；**不伪造任何界面** | spec 声明了状态但业务场景还没做 UI 时，画布必须如实标缺口而不是画一个假界面骗开发 | 仅用于"spec 有、场景无"；场景有但 spec 没写不归它管（属供给侧问题，要告警） | 已验证 |
| 缺口怎么汇总 | 所有占位卡自动汇总成顶部"UI 缺口清单卡"：N 项待补徽标 + 逐条（状态名 + spec 引用 + 说明）；无缺口时该卡不渲染 | 让"这迭代还欠哪些 UI"一眼可数、可排查，也是供给/实现进度的清单 | 缺口清单是占位卡的投影，不手工维护，避免不一致 | 已验证 |
| prepare（填值/点击/滚动到）放哪 | 归**画布编排数据**，不写进业务 spec；动作类型 fill / add-tag / click(selector) / project(同构投影) / scrollTo | 它是"为了让真实页面呈现某状态"的演示驱动，不是业务需求本身，混进 spec 会污染需求源 | prepare 依赖业务 DOM 选择器，是整条链最脆弱处，选择器失效要可观测（同 clip-miss 思路） | 已验证（第一条链 13 fill + 4 add-tag + 开关点击 + 2 project 全部生效）；选择器健壮性仍需更多场景压测 |
| **复杂表单节点怎么穷举状态：cell 状态矩阵** | 对"一个节点内含大量可编辑单元（cell）"的复杂页，在该节点位置插入一个**矩阵节点纵向独占整行**：按页面真实分组（如商品图片/商品信息/价格/规格库存/标签来源/其他/帮卖）纵向分块，每块组头标"组名 · N 态"，组内把**每个 cell 在代码里真实存在的每一种状态**逐一出局部块横排（可换行）；矩阵块宽 1560（约一行 3 个 393 局部块） | 用户两次强调"代码里有的都列出来"，不能用归纳出的标准状态集（空/填/错）代替真实状态：价格 cell 真实状态是"已填·公开 / 已填·隐藏（点公开开关切换）"，多值 cell 是"空 / 已录 N 个（回车添加、×删除）"，货号是"空 / 点自动生成"，图片是"空 / 已选 N 张"。矩阵=对运行时代码状态机的穷举投影，组划分与 cell 顺序严格对齐业务 DOM，不重排不合并 | 仅用于"单节点 cell 多、状态多"的复杂页；简单节点（一个按钮/一行入口）直接用整页或单个局部块，不强行套矩阵，避免为简单流程制造冗余 | 已验证（发布表单 7 组 38 局部块，状态全部来自 publish-product-modal.js 真实分支） |
| 多值标签/开关类 cell 怎么驱动到真实态 | 多值输入用**原生 value setter 设值 + 派发 `KeyboardEvent('keydown',{key:'Enter'})`**，走业务自己在滚动容器上的事件委托生成 chip（不手工拼 chip DOM）；公开/隐藏开关用真实点击 `[data-public-toggle]` 切换 is-hidden | 直接改 value property 不触发框架委托、手工拼 chip 又会和业务真实结构不一致；只有走业务真实事件路径，矩阵块呈现的才是用户真实会看到的标签/开关态 | 依赖业务把多值委托绑在稳定容器上；若业务改用受控组件需对应调整事件 | 已验证（规格 S/M/L、颜色、标签、来源 chip 与价格公开/隐藏均真实生成） |
| 业务数据被模块闭包固化、外部改不动怎么办（如动态流） | 用 **project 同构投影**：对封在业务闭包外无法驱动的区域，按业务真实 DOM 结构 innerHTML 注入同构内容，并 `settle(ms)` 后重放一次以覆盖业务的晚渲染（如动态流 600ms 的 renderList） | 动态流模块加载即 `.slice()` 固化数据，闭包外改原型 DB 无效；要呈现"发布前空列表 / 发布后新增一张卡"，只能投影出与业务同构的 DOM，并在它自身晚渲染之后再覆盖，避免被冲掉 | 投影 DOM 的 class/结构必须逐字对齐业务模板，否则样式与结构失真；这是"驱动不了真实数据管道"时的受控兜底，优先仍走真实交互 | 已验证（①空态空列表 + ⑤发布后新增商品卡，均覆盖 600ms renderList） |
| 列表类页面在流程时序里怎么表达 | **先空态承载、最后一步才出现数据**：流程前段列表用空状态（空插画 + 引导去发布），走完创建动作后的末节点才投影出新增的那条数据；同时发布入口 FAB 必须完整露在底部导航栏上方（tabbed 宿主对 `.wego-fab` 做 bottom 避让） | 用户点名"动态页发布入口被底栏挡了一多半、列表不要一开始就有数据"；空→动作→有数据才是真实用户路径，预置满数据会掩盖入口与空态体验 | 适用于"用户创建后列表才变化"的场景；本来就有初始数据的列表不强制清空 | 已验证（FAB 避让、①空列表、⑤新增卡） |

## 三、渲染与性能

| 场景问题 | 怎么定 | 为什么 | 适用边界 | 状态 |
| --- | --- | --- | --- | --- |
| 一张画布很多页面块，是否一次性全渲染 | **懒加载**：块进入视口附近（IntersectionObserver，rootMargin `500px 300px`）才真实渲染，渲染一次后不再销毁；未到时显示骨架（pending/loading 呼吸占位）；无 IO 环境降级为全量渲染 | 真实 DOM 投影成本高，一次实例化大量页面会卡；预取 500px 保证平移时不闪白 | 预研样本量下足够；未来单迭代块数极多时再评估虚拟回收（当前不做） | 已验证 |
| 浏览态/编辑态如何切换 | 默认**锁定交互**（host pointer-events:none），画布自由拖拽缩放不误触页面；点选某块后该块进编辑态（解锁、品牌绿描边、露出高度把手） | 解决 iframe 平铺"误触"老问题，又保留"点页面可操作真实 UI"的能力 | 拖拽手势在编辑态命中该块时不触发画布平移 | 已验证 |
| 弹窗等浮层怎么不漂到整张画布 | host 建立层叠上下文（transform），host 内 `.modal/.actionsheet/.toast` 由 fixed 改为相对 host 绝对定位；`.modal__panel` **保持组件原生 relative 不改写** | 每个画板是自己浮层的定位基准，蒙层只盖本块、多块平铺互不干扰；尽量少改组件内部结构 | 仅覆盖浮层根定位，不重写组件 DOM/class（遵守组件原样消费） | 已验证 |
| **平铺渲染的通用根因：只加载场景脚本会漏场景私有样式** | 全局 `renderSceneTo`（app.js）原来只 ensureScript 加载场景脚本、从不 ensureStyle 加载场景私有 scene.css；改为 `ensureStyle` 返回就绪 Promise（幂等 + 并发去重 + 出错不挂起），渲染前 `Promise.all([脚本就绪, 样式就绪])` | 依赖全局组件 class（.form-body/.btn/.layout-page）的块看似正常，依赖场景私有 class（.publish-product__img-item/.album-feed__*）的块会失样——表现为图片空态只剩标题、已选图被撑成超高竖排。这是影响**所有平铺场景**的通用隐患，不是迭代画布个例 | 属全局运行时修复（app.js 可直接编辑，非生成物），惠及全部以平铺方式消费场景的工具页 | 已验证（修复后图片空态/已选横排、动态流卡片样式全部正常） |

## 四、视口、缩放与契约

| 场景问题 | 怎么定 | 为什么 | 适用边界 | 状态 |
| --- | --- | --- | --- | --- |
| 画布的主滚动区放哪 | **viewport 是唯一主纵向滚动区**：`overflow-y:auto; overflow-x:hidden`，隐藏原生滚动条，底部留 `--safe-area-bottom-content`；平移/缩放手势已 preventDefault，不会与原生滚动双重滚动 | 场景契约要求恰好一个非嵌套主滚动区，同类 infras 场景（场景管理/组件预览）都是这个范式 | world 绝对定位、横向超宽由手势平移，不出现横向原生滚动条 | 已验证 |
| 缩放范围与初始视图 | 0.06–10；进入时对第一条 P1 流程做 fit（缩放到完整可见并居中）；工具条提供 −/+/适配 | 打开先看到主动线全貌，再放大钻取 | fit 只影响初始，用户可自由缩放平移 | 已验证 |
| 画布作为 infras 场景的样式门槛 | 必须过 `validate-scene-contract.mjs` **0 error**：颜色/间距/圆角/字重/行高/阴影全部走正式 Token，不用裸色/裸值、不留 var fallback、不自定义局部变量、纯展示元素不用 data-dom-id | 与场景管理/组件预览等系统工具场景一致；v5 实验期遗留的 81 项裸值本轮已全部清零 | 设备视口像素（393/852/4000）、定位 top/left、transform 不受 Token 约束，可保留像素 | 已验证 |
| 状态色语义映射 | 主交互/纳入=品牌绿；局部块=信息蓝；缺口/不纳入=警告琥珀；clip 失效=危险红；骨架=skeleton 中性色（纯色+opacity 呼吸，**不用裸色渐变**） | 全画布颜色语义统一、且全部来自 Token；契约不允许 linear-gradient 里写裸色 | 不可再引入 v5 的蓝色主色（#1677ff 已废弃，主色是品牌绿） | 已验证 |
| 如何直达某条流程/某块做验收 | URL 参数（query 必须写在 hash 前）：`?scale=<数值>` 覆盖初始 fit；`?flow=<flowId>` 定位流程；`?all=1` 一次性全量挂载（绕过 IntersectionObserver 懒加载，便于整页截图/断言）；`?origin=1` 从画布左上按 scale 固定铺开（不平移不居中，配合纵向截图）；`?y=<世界坐标>` 在 origin 下纵向直达；`?anchor=<CSS选择器>` 直达任意画布元素（局部块裁剪数百毫秒才收敛，故延迟 600ms 定位一次） | 预研验收、无头整页截图、未来"技能直达某状态块"都需要可分享、可复算的定位链接；origin 模式让世界坐标可换算，anchor 免去逐段猜滚动位置 | 仅预览辅助，不改变默认进入行为；anchor 选择器需 URL 编码 | 已验证 |

## 五、已否决的排版/实现尝试

| 场景问题 | 试过的做法 | 为什么不用 | 状态 |
| --- | --- | --- | --- |
| 页面块形态 | 卡片入口节点 / iframe 平铺 / 静态截图 / Playwright 快照 | 分别存在：不是平铺、误触+视口裁剪、不可编辑、与"直接摆真实 DOM"相悖 | 已否决（沿用前轮结论） |
| 局部块聚焦 | 只对外层场景根 translateY + 裁 host，不处理业务内部滚动 | 目标在 `.layout-scroll` 内被其自身 overflow 裁掉，外层移动穿不透，块内空白 | 已否决 |
| 局部块聚焦 | `target.scrollIntoView({block:'start'})` | 会连带产生横向偏移（价格标签列被裁出左边界）、并带动外层画布滚动 | 已否决，改手动只设纵向 scrollTop |
| 局部块测量 | getBoundingClientRect + 双 rAF 一次性裁定 | 早期几何未稳时测量，先裁矮 host 又污染后续测量，自锁在错误位置 | 已否决，改幂等复位 + 多时点收敛 |
| 局部块裁剪 | 直接把宿主 host 从 852 裁矮到目标高（含"每轮先恢复自然高再裁"的改进版） | 发布表单是贴底弹层 + 内部滚动，host 一变矮弹层卡片就重新贴底、内部滚动容器被压扁，按裁前坐标算的位移失准，有值的 input 和字段 label 被移出裁剪窗；"先恢复再裁"仍要在同一轮再次裁矮，错位依旧 | 已否决，最终改为宿主恒高 + 外层 frame-clip 裁剪窗（见二节） |
| 流程节点排布 | 所有节点放一个 flex-wrap 流里自动换行 | cell 矩阵节点（宽 1560）会和后续整页节点挤在同一行剩余空间，造成错位与大片空白 | 已否决，改纵向 chain + 连续段横排 + 矩阵独占行 + 向下箭头 |
| 骨架动效 | linear-gradient 扫光 shimmer | 契约不允许 gradient 内裸色，且无对应 Token | 已否决，改纯色 + opacity 呼吸 |

## 六、通用生成规则（适配大/小、繁/简迭代）

> 目标：同一套规则既能生成"发布产品"这种大而繁的链路，也能生成只有两三步的小迭代，不为简单流程制造冗余、也不让复杂链路漏状态。下列规则在第一条链落地，状态为"已验证（单链）"，待更多链路复验后升级为技能固定流程。

| 规则 | 内容 | 状态 |
| --- | --- | --- |
| R1 先按代码事实建状态清单，再决定承载形态 | 对每个节点先读运行时代码，列出该节点每个 cell/控件**真实存在的状态分支**（空、已填、自动生成、开关两态、多值 0/N 个、加载、失败、入口子流程…）；状态清单来自代码，不来自经验归纳 | 已验证（单链） |
| R2 按 cell/状态量选承载层级（L0–L2） | **L0** 节点无内部状态或只看上下文 → 一个整页块；**L1** 节点有少量并列状态（≤~6 且跨区域）→ 节点下直接排若干整页/局部块横排；**L2** 节点是含大量 cell 的复杂表单/复杂交互 → 插入 cell 状态矩阵（分组 × 每 cell 全状态）。层级由 R1 清单规模决定，小迭代自然落在 L0/L1，不强行升 L2 | 已验证（单链：动态首/尾=L0，发布空表单=L0，填写中=L2） |
| R3 状态穷举但不重复 | 一个 cell 的同一种状态只出一块；不同 cell 的同类状态（如 5 个价格格各自的公开/隐藏）都要分别出，因为它们是不同单元；组内顺序、组间顺序严格对齐业务 DOM | 已验证（单链，38 块无重复无遗漏） |
| R4 主流程用里程碑整页串，分支/子流程就近标注或独立成流 | 主动线节点（空→填写→填完整→结果）用整页块按连续段横排 + 向下箭头推进；可点入口带出的弹窗子流程（如帮卖分销）在矩阵里标"可点入口"，复杂子流程另起一条带 P 标号的子流程流，不与主流程线交叉 | 已验证（单链，帮卖另起 resale-setup 子流） |
| R5 数据时序沿用户路径表达 | 列表类"先空态、动作后才有数据"；填值/标签/开关/图片全部用 prepare 驱动到真实态；驱动不了的闭包数据用同构 project 投影并覆盖业务晚渲染；"填完整"节点必须真填满（无空字段），不允许只填一半却标注完整 | 已验证（单链） |
| R6 异常与缺口如实占位，不伪造 | 代码里有但 UI 未做的状态（校验阻断/读取失败/保存失败）用规格占位卡 + 代码引用登记；不画假界面、不省略不声明 | 已验证（单链，n5 三占位引 doPublish/faultInjection） |
