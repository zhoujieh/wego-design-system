# 迭代画布 · 排版决策记录（Layout Decisions）

> 用途：预研期把"画布真实输出怎么排才符合验收"的每一个关键决定固化下来，作为后续通用技能（wego-sdd-spec / 画布生成技能）的排版规则来源。
> 维护方式：一条决策一行，固定五栏；**状态只允许 `已验证`（浏览器真实视口实测）/ `待验证`（已实现未实测）/ `已否决`（试过不用，并记原因）**。每条都要能追溯到一次具体实现或走查，不写未经验证的设想。
> 最近更新：2026-09-04（PR #172，三类状态块 + 懒加载轮次）

---

## 一、整体信息架构（自上而下）

| 场景问题 | 怎么定 | 为什么 | 适用边界 | 状态 |
| --- | --- | --- | --- | --- |
| 一张画布先放什么、后放什么 | 顺序固定：①迭代头卡（标题/状态/ID/目标/元信息）→ ②范围卡（纳入 in-scope / 不纳入 out-of-scope 双列）→ ③入口卡（从哪些入口进）→ ④**UI 缺口清单卡**（有缺口才出现）→ ⑤按流程链（flow）逐条纵向堆叠 | 与 spec 的"范围→入口→流程→状态"结构同构，开发 AI 从上到下读就是需求本身；缺口清单前置，避免缺口散落在各流程里被漏掉 | 一个迭代一张画布；跨迭代对比不走此结构 | 已验证 |
| 纳入/不纳入范围怎么区分 | 双列，纳入列绿点、不纳入列琥珀点 | 颜色语义与状态色 Token 一致（success/warning），不额外造色 | 仅表达范围归属，不表达优先级 | 已验证 |
| 流程之间怎么排 | 流程块**纵向**堆叠（每个 flow 一张白卡，大间距分隔）；流程内部"功能点节点 → 状态块"**横向**排列，节点间用右箭头连接 | 纵向=时间/步骤推进，横向=同一节点的并列状态，两个方向语义不混；避免 Figma 式自由连线带来的混乱 | 状态块数量多导致横向超长时，靠画布平移/缩放查看，不折行（折行会破坏"同一节点状态并列"的读取） | 已验证 |
| 一条流程节点头要带什么 | P1/P0 优先级徽标 + 流程标题 + 一句描述 | 开发先看主动线（P1），描述交代这条链在验证什么 | P1 用品牌绿浅底，其余中性 | 已验证 |

## 二、三类状态块（核心）

| 场景问题 | 怎么定 | 为什么 | 适用边界 | 状态 |
| --- | --- | --- | --- | --- |
| 一个"状态"在画布上用什么承载 | 三类：**整页状态块** / **局部状态块** / **规格占位卡**，视觉上用小徽标区分（局部=信息蓝"局部"，缺口=琥珀"缺口"，整页无徽标） | 整页看上下文、局部聚焦字段、缺UI不伪造——三种信息密度需求不同，不能用一种块硬撑 | 三类互斥，一个状态块只属于一类 | 已验证 |
| 整页状态块尺寸 | 默认视口 iPhone 15 Pro：**393 × 852**，真实场景 DOM 全量渲染；高度可拖拽调整 | 与真机视口一致，开发能看到完整上下文；长表单可拖高 | 宽固定 393（设备宽度不是设计 Token，允许像素值）；高默认 852、可拖 | 已验证 |
| 局部状态块怎么来 | **整页渲染 → prepare 驱动到目标状态 → clip 只裁剪聚焦目标**，clip 本身不产生状态；块高=目标元素高+2×pad，蓝描边 | 复用同一套真实渲染，保证局部与整页一致、不会出现"局部是另一套假 UI"；裁剪是纯视图动作 | 适合"只关心某字段组/某单行"的状态（如价格区、某入口行）；需要跨区域看联动时仍用整页块 | 已验证 |
| clip 目标怎么声明 | 编排数据里给 `{selector, closest, pad}`：selector 锚点（优先 data-form-field 等稳定钩子）、closest 上提到要展示的容器、pad 默认 10 | selector 只锚一个元素，closest 决定"聚焦多大范围"，两者解耦 | selector 必须是业务场景里稳定存在的钩子；找不到时**显性红虚线告警**（clip-miss），禁止静默留白 | 已验证 |
| **局部块裁剪的关键坑：目标在业务页内部滚动容器里** | 不能只移外层/裁 host：必须先让目标在**每一层内部纵向滚动祖先**（如 `.layout-scroll`）里滚到可视顶（只设 scrollTop、scrollLeft 锁 0），再上移场景根对齐、最后裁 host 高 | 内部滚动容器有自己的 overflow 裁剪，外层位移穿不透它；`scrollIntoView` 会引入横向偏移并带动外层画布，故改为手动只设纵向 scrollTop | 通用算法，不绑定具体业务；嵌套多个滚动容器时从外到内逐层设置 | 已验证 |
| **局部块测量的关键坑：过早测量会自锁** | 用"复位场景根 transform → 滚内部 → rect 算位移 → 应用"的**幂等**流程，并在双 rAF、160ms、420ms 多次重算收敛；偏移测量优先布局坐标/复位后测量 | 首次测量时业务运行时 init/字体可能未就绪，若此时就裁矮 host，会反过来改变内部几何、污染后续测量形成自锁；幂等复位 + 多次重算可稳定收敛 | 图片类晚到内容若改变目标高度，可能需要再追加重算时点（当前价格组/单行无图片，三次足够） | 已验证 |
| 规格占位卡长什么样 | 393 宽、虚线琥珀边框、浅琥珀底；居中放：感叹号圆点 + "规格已声明·待业务场景补充 UI"徽章 + spec 引用（如 `states.field-validation`）+ 一句说明；**不伪造任何界面** | spec 声明了状态但业务场景还没做 UI 时，画布必须如实标缺口而不是画一个假界面骗开发 | 仅用于"spec 有、场景无"；场景有但 spec 没写不归它管（属供给侧问题，要告警） | 已验证 |
| 缺口怎么汇总 | 所有占位卡自动汇总成顶部"UI 缺口清单卡"：N 项待补徽标 + 逐条（状态名 + spec 引用 + 说明）；无缺口时该卡不渲染 | 让"这迭代还欠哪些 UI"一眼可数、可排查，也是供给/实现进度的清单 | 缺口清单是占位卡的投影，不手工维护，避免不一致 | 已验证 |
| prepare（填值/点击/滚动到）放哪 | 归**画布编排数据**，不写进业务 spec；动作类型 fill / click / scrollTo | 它是"为了让真实页面呈现某状态"的演示驱动，不是业务需求本身，混进 spec 会污染需求源 | prepare 依赖业务 DOM 选择器，是整条链最脆弱处，选择器失效要可观测（同 clip-miss 思路） | 待验证（机制在，选择器健壮性需更多场景压测） |

## 三、渲染与性能

| 场景问题 | 怎么定 | 为什么 | 适用边界 | 状态 |
| --- | --- | --- | --- | --- |
| 一张画布很多页面块，是否一次性全渲染 | **懒加载**：块进入视口附近（IntersectionObserver，rootMargin `500px 300px`）才真实渲染，渲染一次后不再销毁；未到时显示骨架（pending/loading 呼吸占位）；无 IO 环境降级为全量渲染 | 真实 DOM 投影成本高，一次实例化大量页面会卡；预取 500px 保证平移时不闪白 | 预研样本量下足够；未来单迭代块数极多时再评估虚拟回收（当前不做） | 已验证 |
| 浏览态/编辑态如何切换 | 默认**锁定交互**（host pointer-events:none），画布自由拖拽缩放不误触页面；点选某块后该块进编辑态（解锁、品牌绿描边、露出高度把手） | 解决 iframe 平铺"误触"老问题，又保留"点页面可操作真实 UI"的能力 | 拖拽手势在编辑态命中该块时不触发画布平移 | 已验证 |
| 弹窗等浮层怎么不漂到整张画布 | host 建立层叠上下文（transform），host 内 `.modal/.actionsheet/.toast` 由 fixed 改为相对 host 绝对定位；`.modal__panel` **保持组件原生 relative 不改写** | 每个画板是自己浮层的定位基准，蒙层只盖本块、多块平铺互不干扰；尽量少改组件内部结构 | 仅覆盖浮层根定位，不重写组件 DOM/class（遵守组件原样消费） | 已验证 |

## 四、视口、缩放与契约

| 场景问题 | 怎么定 | 为什么 | 适用边界 | 状态 |
| --- | --- | --- | --- | --- |
| 画布的主滚动区放哪 | **viewport 是唯一主纵向滚动区**：`overflow-y:auto; overflow-x:hidden`，隐藏原生滚动条，底部留 `--safe-area-bottom-content`；平移/缩放手势已 preventDefault，不会与原生滚动双重滚动 | 场景契约要求恰好一个非嵌套主滚动区，同类 infras 场景（场景管理/组件预览）都是这个范式 | world 绝对定位、横向超宽由手势平移，不出现横向原生滚动条 | 已验证 |
| 缩放范围与初始视图 | 0.06–10；进入时对第一条 P1 流程做 fit（缩放到完整可见并居中）；工具条提供 −/+/适配 | 打开先看到主动线全貌，再放大钻取 | fit 只影响初始，用户可自由缩放平移 | 已验证 |
| 画布作为 infras 场景的样式门槛 | 必须过 `validate-scene-contract.mjs` **0 error**：颜色/间距/圆角/字重/行高/阴影全部走正式 Token，不用裸色/裸值、不留 var fallback、不自定义局部变量、纯展示元素不用 data-dom-id | 与场景管理/组件预览等系统工具场景一致；v5 实验期遗留的 81 项裸值本轮已全部清零 | 设备视口像素（393/852/4000）、定位 top/left、transform 不受 Token 约束，可保留像素 | 已验证 |
| 状态色语义映射 | 主交互/纳入=品牌绿；局部块=信息蓝；缺口/不纳入=警告琥珀；clip 失效=危险红；骨架=skeleton 中性色（纯色+opacity 呼吸，**不用裸色渐变**） | 全画布颜色语义统一、且全部来自 Token；契约不允许 linear-gradient 里写裸色 | 不可再引入 v5 的蓝色主色（#1677ff 已废弃，主色是品牌绿） | 已验证 |
| 如何直达某条流程做验收 | 支持 URL 参数 `?scale=<数值>&flow=<flowId>`：scale 覆盖初始 fit，flow 让主滚动区定位到该流程 | 预研验收和未来"技能直达某状态块"都需要可分享的定位链接 | 仅预览辅助，不改变默认进入行为 | 已验证 |

## 五、已否决的排版/实现尝试

| 场景问题 | 试过的做法 | 为什么不用 | 状态 |
| --- | --- | --- | --- |
| 页面块形态 | 卡片入口节点 / iframe 平铺 / 静态截图 / Playwright 快照 | 分别存在：不是平铺、误触+视口裁剪、不可编辑、与"直接摆真实 DOM"相悖 | 已否决（沿用前轮结论） |
| 局部块聚焦 | 只对外层场景根 translateY + 裁 host，不处理业务内部滚动 | 目标在 `.layout-scroll` 内被其自身 overflow 裁掉，外层移动穿不透，块内空白 | 已否决 |
| 局部块聚焦 | `target.scrollIntoView({block:'start'})` | 会连带产生横向偏移（价格标签列被裁出左边界）、并带动外层画布滚动 | 已否决，改手动只设纵向 scrollTop |
| 局部块测量 | getBoundingClientRect + 双 rAF 一次性裁定 | 早期几何未稳时测量，先裁矮 host 又污染后续测量，自锁在错误位置 | 已否决，改幂等复位 + 多时点收敛 |
| 骨架动效 | linear-gradient 扫光 shimmer | 契约不允许 gradient 内裸色，且无对应 Token | 已否决，改纯色 + opacity 呼吸 |
