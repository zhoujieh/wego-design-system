## 一句话结论

> 迭代画布 = **按迭代交付 + 范围强一致（入口/流程/状态链）** 的无限画布；
> 页面不是入口卡片、不是 iframe、不是静态截图，而是**对业务场景真实 DOM 的实时投影**——
> 业务场景怎么改，画布刷新即同步；弹窗等子流程按真实层叠（蒙层下页面 + 蒙层上弹窗）平铺展示。

## 关键事实速览

- **交付对象**：开发 AI（按迭代范围 + 交互原型写 kuikly 代码），其次给人快速过目。
- **已确定方向**："直接摆上去"——`app.js` 暴露 `renderSceneTo(routeId, host)`，画布对每个状态块实时渲染真实场景 DOM。
- **已否决方案**：卡片入口节点画布（不是平铺）、iframe 平铺（可交互误触 + 视口裁剪）、纯静态截图（不可编辑）、Playwright 逐页快照（"页面不是都画好了吗，直接摆上去"）。
- **状态链**：**完全由 spec 驱动**（spec 需很全，参考 `docs/sdd-prd/帮卖弹窗spec.md` 范本）；画布直接消费 spec 状态集，不发明、不删减、**状态不能缺失**；spec 有而场景未实现的标注"业务场景待补充"。
- **子流程**：**由 spec 定义**（触发入口/来源页面/展示形态/去向），画布展示与 spec 高度一致、状态不缺失；弹窗以真实层叠展示（蒙层下为来源页面，蒙层上为弹窗），复用真实弹窗运行时。
- **默认视口**：iPhone 15 Pro（393×852），高度可拖拽自调；缩放 6%~1000%，初始自动适配。
- **通用机制**：每个画板容器（`transform: translateZ(0)`）是内部浮层（弹窗/蒙层/键盘/toast）的定位基准，只覆盖本画板。
