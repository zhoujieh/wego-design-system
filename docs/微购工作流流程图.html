任务启动 wego-github-delivery
启动清单 · 分支巡检 · 交付单元核对
⌄
  • 新任务开工前按启动清单执行：判断上下文 → 分支巡检收口 → 环境同步 → 交付单元核对 → 独立 worktree。
  • 核对结果：matched 复用分支/worktree/PR；new 无匹配才新建；conflict 停止询问。
  • 每个交付单元使用独立 worktree，主 worktree 只保留 main 用于同步。
  • 会话前置读取经验摘要（EXPERIENCE.md），避免重复踩坑。

需求确认 wego-product
创建迭代 · 确认 prototype_brief
⌄
  • 创建迭代 → 写需求规格说明 spec.md（唯一需求源）→ submit-brief 进入 in-development（简报开放开发，可反复重提）。
  • 简报充分性守门：目标/范围/入口/关键路径/状态必须非空，open_questions 必须清空。
  • 数据必须有产生入口（发布/新建/录入流程），禁止静态种子降级；关键路径首尾闭环。

设计实现 wego-design
本地迭代 · 场景实现 · 自动推送 PR
⌄
  • 已确认简报即设计授权：范围内布局、组件、Token、反馈由设计阶段自主完成。
  • 流程：设计意图 → 语义区域 → 范式匹配/自主组合 → 组件映射 → 实现 scene.js/css/route.json → 场景契约预检。
  • 完成一轮实现后自动推送远端分支并创建/更新同一 PR，返回本地 + 在线两个预览链接。
  • 场景数据优先取自原型数据库 WEGO_PROTOTYPE_DB，不临时编造。

旁路 · 设计系统 / 工作流维护 wego-uxsystem-iterate
组件 / Token / Preview / UI Kit · 经验沉淀
⌄
  • 组件、Token、Preview、UI Kit 变更仍走用户验收流程；工作流权威源维护免业务验收，验证通过走短周期 PR 自动合并 main。
  • 经验沉淀：业务技能识别信号（纠正/偏好/返工/踩坑）→ 写草稿 → 收口扫描 → 四层分流（L1 事实 → L2 摘要 → L3 场景技能 → L4 正式规则）。
  • 业务场景功能不得放入技能目录或设计系统权威源。

决策门 · 用户明确验收通过？
普通反馈不构成验收授权
⌄
  • 是（"验收通过""可以合并"） → 进入验收收口，固化、验证并合并 main。
  • 否（"改好了""继续""再调整"） → 回到本地迭代累计修改，自动更新同一 PR，不合并。
  • 实现完成、检查通过、用户查看页面，都不等于合并授权。

验收收口 wego-design
5 维校验 · 冻结 · 完整验证
⌄
  • 输出 5 维度一致性校验清单（范围 / 入口 / 关键路径 / 状态 / 数据契约），用户逐项确认。
  • 连续执行 confirm-brief（简报确认）→ submit-prototype（一步冻结到 frozen）。
  • 运行完整静态验证（full --strict / build-routes --check / sync-lib --check），任一失败先修复再推送。
  • 经验收口扫描必须在 worktree 清理前完成。

合并 + 收尾 wego-github-delivery
合并 main · 四步收口清理
⌄
  • 合并前再次同步 main、复验，通过后合并 PR 进 main。
  • 四步收口：停预览服务删记录 → 删远端分支 → 删本地 worktree → 主 worktree 同步 main。
  • 合并是异步事件，本地收口由后续启动巡检兜底补齐。

贯穿全程 · 经验沉淀 wego-uxsystem-iterate
信号 → 草稿 → 收口扫描 → 四层分流
⌄
  • 识别信号（用户纠正 / 表达偏好 / 返工 / 踩坑）→ 向 .tasks/experience-inbox.json 追加草稿。
  • 交付单元收口时扫描草稿并分流：一次性 → L1 事实 + L2 摘要；同场景 ×2 或流程固定 → 毕业 L3 场景技能；跨场景硬约束 → 升格 L4 正式规则。
  • 零信号零动作，沉淀后告知用户，不新增确认门禁。

迭代状态机

状态由 iteration-record.mjs 维护；只有用户明确表达才推进，时间经过 / 完成修改 / 通过检查都不推进
draft
写 spec.md
→
in-development

→
prototyping
设计实现 + 自动推 PR
→
frozen

反馈分流：范围内视觉/布局/组件/交互调整 → 原迭代继续改（不 invalidate）；改变目标/范围/入口/关键路径/状态/数据 → 失效简报重提确认；frozen 后调整 → 先回 prototyping 累计，用户再次明确验收后才重新冻结。暂停/终止状态：blocked | cancelled | superseded。
