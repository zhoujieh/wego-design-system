任务启动 wego-github-delivery
启动清单 · 分支巡检 · 交付单元核对
⌄
  • 新任务开工前按启动清单执行：判断上下文 → 分支巡检收口 → 环境同步 → 交付单元核对 → 独立 worktree。
  • 核对结果：matched 复用分支/worktree/PR；new 无匹配才新建；conflict 停止询问。
  • 每个交付单元使用独立 worktree，主 worktree 只保留 main 用于同步。
  • 会话前置读取经验摘要（EXPERIENCE.md），避免重复踩坑。

需求确认 wego-product
创建迭代 · 薄档提交 · 原型循环
⌄
  • 创建迭代 → 写简要需求规格说明 spec.md（唯一需求源）→ submit-brief 进入 in-development 原型循环（spec 随改随重提，每轮反馈写回字段）。
  • 两档守门：薄档（提交时）目标/范围/入口/关键路径非空即可，states/数据契约可空、open_questions 可暂存；终版（终局确认时）全量结构 + 充分性 + open_questions 清空由脚本守门。
  • 数据必须有产生入口（发布/新建/录入流程），禁止静态种子降级；关键路径首尾闭环。

设计实现 wego-design
本地迭代 · 场景实现 · 自动推送 PR
⌄
  • 立项确认 + 已提交简要简报即原型授权：范围内布局、组件、Token、反馈由设计阶段自主完成。
  • 流程：设计意图 → 语义区域 → 范式匹配/自主组合 → 组件映射 → 实现 scene.js/css/route.json → 场景契约预检。
  • 完成一轮实现后自动推送远端分支并创建/更新同一 PR，返回本地 + 在线两个预览链接。
  • 场景数据优先取自原型数据库 WEGO_PROTOTYPE_DB，不临时编造。

决策门 · 用户明确验收通过？
普通反馈不构成验收授权
⌄
  • 是（"验收通过""可以合并"） → 进入终局确认：AI 补全终版 spec → 核对填写验收账本 → 展示补全 diff 与账本，用户过目确认后固化、验证并合并 main。
  • 否（"改好了""继续""再调整"） → 回到本地迭代累计修改，自动更新同一 PR，不合并。
  • 实现完成、检查通过、用户查看页面，都不等于合并授权。

终局确认（与验收合一） wego-design
补全终版 spec · 账本勾销 · 冻结
⌄
  • 补全终版 spec.md（只能补细节不能减内容）并重新 submit-brief → 逐项核对填写验收账本 acceptance.json（入口/关键路径/状态/数据契约，每项标状态与证据）→ 展示补全 diff + 账本清单请用户过目。
  • 用户过目确认后连续执行 confirm-brief（终局守门：全量结构 + 充分性 + open_questions 清空 + 账本全绿）→ submit-prototype（账本复验 + 一步冻结到 frozen）。
  • 运行完整静态验证（full --strict / build-routes --check / sync-lib --check），任一失败先修复再推送。
  • 经验收口扫描必须在 worktree 清理前完成。

合并 main · 四步收口清理
⌄

贯穿全程 · 经验沉淀 wego-uxsystem-iterate
信号 → 草稿 → 收口扫描 → 四层分流
⌄
  • 识别信号（用户纠正 / 表达偏好 / 返工 / 踩坑）→ 向 .tasks/experience-inbox.json 追加草稿。
  • 交付单元收口时扫描草稿并分流：一次性 → L1 事实 + L2 摘要；同场景 ×2 或流程固定 → 毕业 L3 场景技能；跨场景硬约束 → 升格 L4 正式规则。

高频踩坑提示

源自 experience/EXPERIENCE.md 经验摘要，避免重复踩坑
  • 简报：spec 多轮更新后、提交前必须全文搜索统一旧描述，保证前后一致；每个入口写清触发方式、对象、按钮层级与后续行为，不明点入 open_questions 不猜测。
  • 设计稿：Figma 还原前必须确认设计稿内容，无法访问就请用户描述或给切图，禁止凭组件名猜样式。
  • 实现：切图要偏移且不裁剪用 img 标签定位（不用 CSS 背景图，会被裁剪），img 路径相对 index.html；新存储 key 按 wego.{domain}.{entity} 命名，不迁移旧 key。
  • 交付：每次推送 PR 必须等 publish 通过并 curl 校验部署产物后返回在线链接，不得只给本地链接；PR 合并后必须清理本地分支 / worktree / 预览记录。
  • CI：改 design/runtime 必须同步 lib 副本；Pages 预览标红多为部署延迟，先比对 .wego-deployment-sha 再排查构建。
  • 结构：业务场景功能不得放入技能目录 / 设计系统权威源，全局业务运行时直接放 wego-app/js 与 wego-app/css。
