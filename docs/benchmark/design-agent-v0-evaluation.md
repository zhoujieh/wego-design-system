# Design Agent V0 Benchmark 评价规则

> 用途：验证新的通用 Design Agent V0 是否真实优于当前 `wego-design-system + Codex` 工作流。
> 第一条固定用例：`docs/benchmark/001-快捷发布产品.md`。

## 1. 对照组

### A：当前工作流

- 当前 `wego-design-system` 主线；
- 当前正式技能与设计系统消费方式；
- 使用全新无历史上下文会话；
- 使用 `001-快捷发布产品.md` 原始提示词；
- 不人工补充提示词。

### B：Design Agent V0

- 通用 Design Agent Core；
- 微购 Project Context v0；
- 正式代码组件；
- Component Registry / Resolver；
- Live Prototype / Semantic Review；
- 使用相同原始提示词；
- 不人工补充额外业务事实。

## 2. 执行要求

1. A、B 均使用相同原始 Benchmark 提示词。
2. 每次运行使用新会话和干净产物环境。
3. 两边各至少独立执行 3 次。
4. 不因某一次生成结果临时修改 Benchmark。
5. 用户反馈只用于记录“达到可验收状态需要多少轮”，不能在 A/B 之间使用不同验收标准。
6. 评价以真实可运行原型为准，不以最终说明文本或静态截图代替。

## 3. 核心指标

每次运行记录以下指标。

| 指标 | 定义 | 越低越好 |
| --- | --- | --- |
| 业务理解错误数 | 对业务对象、单/多值、入口、发布结果、编辑能力等已知事实理解错误 | ✅ |
| 组件错用数 | 有正式组件但选择了语义不匹配组件 | ✅ |
| 自造 UI 数 | 正式组件可以覆盖，但业务实现另造结构/样式 | ✅ |
| 组件实现违规数 | 组件内部 DOM、状态、Variant、Token 或行为被错误重写 | ✅ |
| 关键状态遗漏数 | 默认、识别/处理中、失败、完成、重新编辑等必要状态缺失 | ✅ |
| 主路径断点数 | 核心流程存在无法继续、结果不可感知或返回关系错误 | ✅ |
| 首轮需修改问题数 | 首次可运行原型中需要用户指出的问题总数 | ✅ |
| 达标对话轮数 | 从首次结果到用户认为可验收所需反馈轮数 | ✅ |

补充记录：

- 是否一次生成即可运行；
- 375 / 393 视口是否出现基础问题；
- 是否出现运行时错误；
- 用户主观判断：A / B / 无明显差异。

## 4. 第一条 Benchmark 的固定业务事实

以下内容来自 `001-快捷发布产品.md`，评分时不得由评价者自行增加新的需求口径：

- 快速录入产品名、售价、货号、规格、颜色、重量、库存、标签和来源；
- 上传产品图片；
- 设置可见范围；
- 规格、颜色、标签、来源支持一次录入多个内容；
- 其他字段为单值；
- 发布完成后新产品出现在动态内容中；
- 已有信息支持后续重新编辑。

如果需要评价更细的交互质量，应记录为“用户反馈/设计质量观察”，不得反向改写固定 Benchmark 输入。

## 5. 组件语义重点观察

第一条 Benchmark 优先观察以下关系：

- `Button`：主行动是否唯一且语义清晰；
- `Cell`：信息行/设置行是否错误自造；
- `Search`：若场景使用搜索，是否使用正式能力；
- `Tag`：规格/颜色/标签等多值表达是否滥用 Tag 或反向自造 Tag；
- `Switch`：布尔设置是否使用正确控制；
- `Checkbox`：多选是否由明确选择控件承担；
- `Result`：完成/失败/空结果是否使用正确结果态语义；
- `BottomActionBar`：底部主行动是否由正式容器承载。

注意：Resolver 不要求所有 Intent 唯一映射到一个组件。评价重点是“是否存在明显更合适的正式组件却被错误替代”。

## 7. V0 通过条件

完成至少 A×3、B×3 后再做结论。

B 必须同时满足：

1. 平均业务理解错误数低于 A；
2. 平均“组件错用 + 自造 UI + 组件实现违规”显著低于 A；
3. 平均关键状态遗漏不高于 A；
4. 平均达标对话轮数低于 A；
5. 用户明确判断 B 的工作方式优于当前“Codex + 浏览器”流程。

如果只在视觉观感上变好，但业务理解、组件正确性和迭代轮次没有改善，V0 判定为未验证成功。

## 8. 第一阶段不评价的内容

V0 暂不以以下能力作为成功条件：

- Figma 输出质量；
- GitHub PR 自动化；
- 多项目能力；
- 企业级知识导入；
- Experience 自动学习；
- 多 Agent 协同；
- SaaS 部署和多人协作。

这些只有在 V0 核心假设通过后才进入下一阶段。
