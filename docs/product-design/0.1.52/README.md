# 产品设计

将早期的产品创意、线上 URL 和静态截图转化为可供团队评审、打磨并持续推进的原型。

## 何时使用此插件

当你希望理解现有体验、探索新方向，或创建可供人们交互和评审的原型时，请使用产品设计。你可以从书面简报、截图、设计图、线上 URL、现有原型，或你为未来工作保存的产品参考开始，例如产品 URL、Figma 文件、截图、代码库路径或设计 Token。

## 开始使用

试着问：

`@Product Design 帮我开始`

插件会引导你如何保存有用的产品上下文，例如产品 URL、相关 Figma 文件、截图、代码库路径、Storybook 链接、Token 和品牌资产。

已经有想做的任务了？跳过设置，直接请求你需要的工作流。

## 示例工作流

| 工作流 | 尝试这样说 | 技能 | 结果 |
| --- | --- | --- | --- |
| 为新产品创意制作原型 | `Build a clickable prototype for this product idea` | `构思` → `图转代码` | 三个视觉方向供选择，然后根据你的选择生成可运行的原型 |
| 复刻一个线上界面 | `Clone this URL into an editable prototype` | `URL 转代码` | 一个基于可见源的可编辑本地原型 |
| 实现选定的设计 | `Turn this selected mockup into a responsive prototype` | `图转代码` | 对你所选设计的忠实、可交互实现 |
| 探索视觉方向 | `Turn this product idea into three visual directions` | `构思` | 可供比较的不同概念，帮助你决定构建什么 |
| 重新设计现有界面 | `Redesign this settings screen and show me three directions before building` | `构思` → `图转代码` | 三个扎实的设计方案，只有在你选定方向后才继续制作原型 |
| 审计产品流程 | `Audit this onboarding flow and identify the highest-impact UX and accessibility issues` | `审计` | 以截图为依据、与体验步骤相关联的发现 |
| 研究用户摩擦 | `Research the biggest UX problems users are reporting for this product` | `研究` | 基于来源的用户痛点、严重程度、置信度和产品机会视图 |
| 评审原型 | `Critique this prototype and identify the highest-impact design issues` | `审计` | 基于证据的 UX、设计和可访问性评审 |
| 分享原型 | `Share this prototype with the team` | `分享` | 在你选定托管目标后生成一个可分享的可用 URL |

### 提示：使用批注精修原型

在应用内浏览器中编辑原型时，你可以使用批注工具指向想要修改的确切元素。直接在 UI 上添加评论或调整 CSS 值，然后将批注发送回来，以便快速、精准地进行修改。

## 集成

当连接可用工具时，产品设计可以使用它们：

| 工具 | 解锁的能力 |
| --- | --- |
| 浏览器、Chrome 或 Playwright | 捕获和检查线上产品界面，用于审计、克隆和原型 QA |
| Figma 或 Canva | 将原型工作带入可评审的设计工作区，并使用现有设计上下文 |
| 图像生成 | 探索视觉替代方案，并为选定方向生成资产 |
| Sites、Vercel 或其他可用托管工具 | 在你选定部署目标后发布可运行的原型 |

当不需要连接工具时，你仍然可以从书面简报、截图、图像文件、URL、本地原型或已保存的设计上下文开始。
