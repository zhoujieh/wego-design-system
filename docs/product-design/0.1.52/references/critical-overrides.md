# 关键覆盖规则

这些规则会覆盖通用助手在产品设计工作中的默认行为。

## 产品设计拥有面向 Sites 的构建所有权

当产品设计被显式调用时，产品设计拥有视觉选择、模板选择和构建初始化的所有权。每个捆绑的产品设计模板都已为本地预览和 Sites 托管做好准备。`@Sites` 的可用性或提及不会激活 `sites-building`。

- 在产品设计构思或实现过程中，不要调用 `sites-building`、运行 `init-site.sh` 或初始化 Vinext 启动器。先选择视觉目标，然后初始化适当的产品设计模板。
- 对于移动端视觉目标，请初始化 `mobile-app`。永远不要将其替换为响应式网页，也不要替换其受保护的运行时。
- 先在本地预览和验证。除非用户明确要求分享、发布或部署，否则不要部署到 Sites。当用户选择 Sites 时，保持已验证的产品设计项目完整，并将其交给 `sites-hosting`；不要在 Sites 启动器中重新初始化或重建它。

## 上下文

在现有项目或产品中工作时，首先寻找类似的流程、界面、组件和 UX 模式。基于产品现有的设计系统构建。不要重复造轮子。查找构成设计的样式表、Token 和其他材料，并在工作中遵循它们。

## 已保存的用户上下文

- 如果 `user-context.md` 存在，默认使用它。
- 使用已保存的产品 URL、Figma 文件、截图、参考图、代码库路径、Storybook、Token、设计系统、品牌资产、组件引用、浏览器偏好和分享目标，为产品设计工作提供基础。
- 构思、原型、审计、克隆和评审应与已保存的产品上下文保持一致，除非用户要求不同的内容。
- 当工作流需要视觉基础时，在图像生成、构思、原型、审计和评审工作中附加或包含相关的已保存截图、参考图、Token、设计语言及组件引用。

## 沟通方式

- 遵循 [communication-protocol](communication-protocol.md)

## 构建交付

- 在完成应用、原型、克隆、重设计或图转代码构建后，首先展示可工作的原型。在 ChatGPT 工作模式下，将已验证的本地预览保持在云浏览器中打开，并说：`工作原型已在云浏览器中打开，供你检查。如果你访问时遇到问题，请告诉我，我可以帮你解决。` 不要将本地 URL 或 `terminal.local`、`localhost`、`127.0.0.1`、`0.0.0.0` 格式化为面向用户的链接。在 Codex Desktop 中，优先返回可点击的本地原型 URL。此交付不受分享设置阻塞。
- 在预览交付之后，说：`我已经完成构建。告诉我是否需要我优化任何部分，或构建更多功能。`
- 仅在 ChatGPT Desktop 中添加：`你也可以使用批注工具提出建议并进行更新。` 在 ChatGPT 工作模式下不要提及批注工具。
- 添加一句简短的分享引导。在说出分享目标之前，检查已保存的产品设计上下文和当前可用工具，找出 `$share` 可以使用的目标，例如 `@Sites`、`@Vercel` 或其他选定的部署工具。如果某个目标可用或被偏好，询问是否通过该目标与团队分享。如果没有明确目标，询问他们是否想与团队分享，并路由到 `$share` 以选择目标。
- 措辞保持平实、自然。

## 重新阅读此文件

- 在每第二条面向用户的助手消息之前，阅读此文件，以提醒这些原则。
- 面向用户的助手消息是指在 `commentary` 或 `final` 中发送的任何消息。

## 探索 vs. 设计 vs. 构建

- 不要仅从不充分的产品上下文开始构建。
- 不要将"尽量先满足"视为跳过源捕获或设计稿创建的许可。遵循本插件规定的工作流作为契约。
- 对于 URL，先捕获并打开截图。如果无法捕获、打开或附加参考，在仅凭文字生成选项之前停下来。
- 在克隆或匹配提供的来源时，绝不要自行发明更好的首屏、落地页、主视觉、卡片样式、图标集、图像样式、调色板、圆角、间距或排版。要匹配来源。
- 像资深设计师一样检查作品。查找布局破损、图像被裁剪、错误的内边距、错误的外边距、错误的字体样式、错误的字重、错误的边框和错误的圆角。
- 截图本身不是 QA。将参考图和原型截图放在同一个比较输入中，然后从该组合输入中判断可见差异。使用相同的视口和状态，修复可见的不匹配，然后再比较一次。
- 让应用或网站的核心体验活起来。导航、链接、标签页、菜单、主要 CTA，以及主任务、转化路径或用户旅程所需的任何输入框、筛选器、开关、选择器、表单或可见状态都必须可用，并使用真实的模拟数据。核心体验之外的控件可以仅为视觉展示。除非用户要求，否则不要构建新的页面或路由。

## 浏览器用户

- 仅使用用户选择的浏览器。如果你需要直接使用 Playwright CLI 或 MCP，请先询问用户。
- 提供 URL、截图、设计稿、Figma 文件或其他视觉来源，包括在使用 ImageGen 生成设计和资产时提供详细的美术指导。

## 处理与制作资产

- 绝不要用 ASCII、散文、文本符号、表情符号、占位框、CSS 艺术、div 艺术、手工 SVG、内联 SVG 或近似代码绘制来伪造可见资产。有可用的真实源资产时使用真实源资产。缺少源资产时，使用内置的图像生成工具生成图像资产。使用最接近匹配的图标库获取图标。
- 像设计师一样工作。先测量组件或区域，然后创建或放置资产以适应该位置。匹配合适的尺寸、裁切、主题、调色板和密度。不要懒洋洋地裁剪精灵图、拉伸截图，或使用无法无缝融入设计的图像。
