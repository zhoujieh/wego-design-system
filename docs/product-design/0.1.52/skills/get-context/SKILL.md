# 获取上下文


在要求设计、构建、原型制作、克隆、重新设计或生成产品 UI 方向的产品设计请求开始时运行此技能。

当以下任何一项不清楚时，使用提问模式：

- 正在设计、重新设计或扩展的产品、站点、功能、工作流、组件或屏幕是什么
- 该功能、变更、应用或网站应帮助用户做什么
- 当从视觉来源或简报中不明显时，目标是网站、桌面/网页应用还是移动应用

不要重复询问已回答的问题。当两者都清楚时，用一句简洁的注释回放简报和默认值，命名下一个工作流，并在同一轮中继续。回放不是请求批准。用户可以随时纠正风格、范围或交互性。

硬边界：当设计目标或预期用户成果仍然缺失时，不要实现 UI、搭建原型、启动服务器或创建文件。

## 关键覆盖规则

- 继续之前，先参考插件路由 [$index](../index/SKILL.md)。
- 遵循 [$critical-overrides](../../references/critical-overrides.md)。

## 用户上下文

开始前，加载 [$user-context](../user-context/SKILL.md)，并在本地 shell 访问可用时运行其预检脚本。

在相关时，使用已保存的产品 URL、Figma 文件、截图、参考图像、代码库路径、Storybook、设计令牌、设计系统、品牌资产、组件参考、浏览器偏好和分享目标作为基础材料。

不要检查每个已保存的参考。只检查当前任务需要的。

## 移交给下一个工作流

1. 当下一个工作流已经明确时，在发送简报回放之前阅读该技能。不要仅命名一个你尚未阅读的技能。

2. 在执行 `$ideate`、`$url-to-code` 或 `$image-to-code` 之前，用一句简洁的用户可见注释回放最低限度简报和任何默认值。

3. 如果目标和预期用户成果清楚，在同一轮中继续到下一个工作流。不要等待明确确认。如果用户提供反馈，吸收并纠正方向。

4. 在开始一个复杂的应用、原型、克隆、重新设计或构建之前，发送一条简短的设定期望注释并继续。示例：

```text
这种构建通常需要大约 10-15 分钟，雄心勃勃的可能需要更长时间。喝杯咖啡或处理其他事情的好时机；我会继续推进，并在原型准备好后带回来。
```

对于微小的静态变更、快速审计、简单研究、仅设置或仅分享请求，不要发送此注释。

完成意味着设计目标和预期用户成果已明确，默认值已回放，并且任何已确定的下一个技能已阅读。
