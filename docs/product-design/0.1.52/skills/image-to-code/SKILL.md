# 图像转代码

你的任务是将视觉目标图像转换为高质量、交互式的网站或网页应用。

## 关键覆盖规则

- 继续之前，先参考插件路由 [$index](../index/SKILL.md)。
- 遵循 [$critical-overrides](../../references/critical-overrides.md)。

## 用户上下文

开始前，加载 [$user-context](../user-context/SKILL.md)，并在本地 shell 访问可用时运行其预检脚本。

在相关时，使用已保存的产品 URL、Figma 文件、截图、参考图像、代码库路径、Storybook、设计令牌、设计系统、品牌资产、组件参考、浏览器偏好和分享目标作为基础材料。

不要检查每个已保存的参考。只检查当前任务需要的。

### [重要] 在 ChatGPT 工作模式中预览原型

启动 `sites-preview` 不等于验证。验证需要在云浏览器中打开 `http://terminal.local:4173/`，检查渲染后的页面，测试主要交互，检查浏览器控制台错误，并通过设计质量保证。

不要用 HTTP 健康检查、构建成功、预览服务状态或部署成功来替代浏览器验证。如果无法使用云浏览器，报告验证受阻。

对于 ChatGPT 工作模式中的本地原型验证和设计质量保证：

1. 如需安装依赖。项目必须有一个 npm `dev` 脚本。
2. `sites-preview` 运行 `npm run dev -- --host 0.0.0.0 --port 4173 --strictPort`。`dev` 脚本必须接受这些参数。
3. 对于产品设计 Vite 启动器，使用 `"dev": "vite"`。配置 Vite 时设置 `server.host: "0.0.0.0"` 和 `server.allowedHosts: ["terminal.local"]`。保留现有 Sites 项目支持的开发脚本；不要替换其运行时。
4. 从站点根目录运行 `sites-preview start "$PWD"`。
5. 在云浏览器中打开 `http://terminal.local:4173/`。不要使用 `localhost`、`127.0.0.1`、`0.0.0.0`、HTTPS 或其他端口。
6. 在报告完成前验证渲染的站点及其主要交互。
7. 保持本地预览对用户开放。除非用户明确要求分享、发布或部署，否则不要部署到 Sites。

## 工作流程

重要提示：这不是指导，这是需要完成的检查清单。

1. 除非你有选定的图像、截图、模型或图像生成结果要复现，否则不要开始。仅书面简报是不够的。

2. 在构建之前确定确切选定的视觉目标。

    - 如果用户选择了编号的 `$ideate` 选项，使用最近一组创意中第 N 张显示的生成图像结果。不要使用原始概念规划顺序或图像生成提示提交顺序。
    - 仅当概念名称列表明确按照相同的显示图像顺序书写时，才使用 `$ideate` 中的概念名称列表。
    - 生成图像结果 ID、选定的图像附件、截图、模型或 Figma 框架比单纯的序号更强。优先使用该确切参考。
    - 如果无法明确确定选定的结果，在实现前停止并询问用户命名概念或重新附加/选择图像。永远不要猜测并构建相近的选项。

    移动端运行时例外：1:1 保真度仅适用于设备屏幕内的应用自有内容。`PhoneFrame`、`StatusBar`、`HomeIndicator`、`KeyboardDock` 和设备资源属于模板拥有的基础设施。即使参考图像省略了它们、展示了不同的设备外壳或在内包含外壳，也要保留它们。永远不要将设备外壳作为图像资源来复现。

3. 将确定的图像作为要复现的设计。

4. 如果提供的设计是移动端视口，构建一个移动应用。在为此创建新的本地应用时，使用 [local-prototype-preflight](../../references/local-prototype-preflight.md) 并带上 `--template mobile-app`。如果不清楚，默认为桌面端。

   在使用 `mobile-app` 模板规划或实现之前，阅读其 `AGENTS.md` 并遵循其运行时和组件指导。

5. 审查参考设计，清点设计中的每个图像资源，并使用图像生成工具为每个资源创建单独的图像。放大查看，确保不会遗漏任何需要生成的资源。

    示例包括：

    - 首屏大图，包括全出血图像背景
    - 精选文章配图
    - 缩略图
    - 装饰性插图
    - 纹理和背景图案
    - 标志
    - 产品图片
    - 头像

    规则：

    - 关键规则：永远不要使用自定义 div 艺术、CSS 艺术、内联 SVG、手工制作的 SVG、HTML 元素绘图、div/span 形状、CSS 绘图、渐变、表情符号或文字字形来代替真实的图标和图像资源。使用内置的图像生成工具生成图像，并使用最匹配的图标库获取图标。
    - 如果文字是图像资源的一部分，将其保留在图像资源中。示例包括全出血首屏大图、标牌、海报、包装、店面、文章配图以及类型属于视觉本身的插图。不要裁剪背景图像并用透明文本框、HTML、CSS 或单独的覆盖层重新创建该文本，除非源图清楚地显示了位于图像顶部的可编辑 UI 文本。
    - 在参考暗示自定义视觉内容的地方，不要使用通用占位符。
    - 生成的资源必须与参考模型具有相同的艺术方向、调色板、渲染风格和设计语言。
    - 内置的图像生成工具不支持透明图像；需要透明时，对生成的资源进行后处理。
    - 对于移动原型，不要清点或生成设备边框、刘海屏、状态栏、时钟、信号或电池指示器或主屏幕指示器。移动运行时拥有这些元素。

### 并行资源生产

在清点和测量参考资源后，在主代理构建应用结构时，生成最多三个资源子代理。

给每个子代理一次一个光栅资源任务，附带其参考裁剪、精确尺寸、焦点、样式、输出路径和消费组件。资源子代理生成、检查、保存并仅报告资源路径。它们不得编辑源代码、运行浏览器或部署。

优先处理首屏关键资源，然后复用代理处理辅助资源。不要委派标准 UI 图标或提供的品牌标志。

6. 定义页面的所有部分。对于每个部分，仔细测量布局、元素之间的间距以及元素本身的大小和间距。

7. 找到与目标设计匹配的免费可用字体。

8. 找到与目标设计匹配的免费可用图标库。不要默认使用 Lucide 图标。搜索最佳匹配。

    规则：

    - 关键规则：不要创建自定义内联 SVG、手工制作的 SVG、HTML 元素绘图、div/span 形状、CSS 绘图、渐变、表情符号或文字字形。使用内置的图像生成工具生成资源，并使用最匹配的图标库获取图标。

9. 使用 [local-prototype-preflight](../../references/local-prototype-preflight.md) 开始构建应用。除非用户要求静态模型、完整的生产行为或不同的范围，否则通过以下方式为应用或网站注入活力：

    - 可用的导航、链接、标签页、菜单和主要行动号召。
    - 主体验中显示的功能性输入、筛选器、切换、选择和表单。
    - 可见的 UI 状态：悬停、聚焦、选中、打开/关闭、加载、空状态和成功状态（在相关时）。
    - 当产品具有主要任务、转化路径或用户旅程时，使其从头到尾正常工作。

    核心体验之外的控件可以是纯视觉的。除非有要求，否则不要构建认证、持久化、后端/API 调用、集成或详尽的边缘情况。

    规则：

    - 在继续之前，将你生成的每个图像资源放入其位置。我再说一遍，替换所有占位符，包括 CSS/SVG 占位符，然后再继续。
    - 不要将核心体验中的控件保留为静态装饰。不要创建新页面或路由，除非用户要求。

10. 运行本地应用。

11. 使用 [$index](../index/SKILL.md#browser-choice) 中的浏览器选择规则捕获本地应用。

12. 将 [design-qa](../design-qa/SKILL.md) 作为阻塞式构建门禁运行。

    步骤：

    - 在编写质量保证报告之前，打开参考图像和最新原型截图。
    - 比较相同的视口和相同的交互状态。如果不匹配，先捕获缺失的视图。
    - 将质量保证报告保存为项目根目录下的 `design-qa.md`。
    - 修复 P0/P1/P2 问题，再次捕获应用，并重复直到质量保证报告显示 `final result: passed`。
    - 不要在 P3 打磨上持续循环。将任何剩余的 P3 作为后续迭代备注包含在内。
    - 如果源捕获、原型捕获或视觉比较受阻，停止。`design-qa.md` 必须显示 `final result: blocked`。
    - 除非 `design-qa.md` 存在并显示 `final result: passed`，否则不要移交。

13. 移交应用或网站。

    - 仅在 [design-qa](../design-qa/SKILL.md) 通过后才移交。
    - 保持原型在本地运行。
    - 保持本地预览对用户开放。在 ChatGPT 工作模式中，告诉用户在云浏览器中检查原型；不要提供可点击的本地 URL。在 Codex 桌面版中，提供可点击的本地 URL。除非用户明确要求分享、发布或部署，否则不要部署到 Sites。
    - 预览移交后，使用 `critical-overrides.md` 中的共享构建移交。不要添加不同的完成消息。
    - 包含 [critical-overrides](../../references/critical-overrides.md#build-handoff) 中的构建后迭代和分享提示。
