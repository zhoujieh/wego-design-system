# URL 转代码

如果用户明确调用此技能，继续。

仅当用户要求克隆或复现当前站点时才继续。

如果用户说 `like`、`better`、`redesign` 或 `improve`，返回 [$index](../index/SKILL.md)。

将 `<target-url>` 克隆为真实的交互式仅前端本地应用或网站。克隆应该看起来和交互起来像源站点。

## 关键覆盖规则

- 继续之前，先参考插件路由 [$index](../index/SKILL.md)。
- 遵循 [$critical-overrides](../../references/critical-overrides.md)。

## 用户上下文

开始前，加载 [$user-context](../user-context/SKILL.md)，并在本地 shell 访问可用时运行其预检脚本。

在相关时，使用已保存的产品 URL、Figma 文件、截图、参考图像、代码库路径、Storybook、设计令牌、设计系统、品牌资产、组件参考、浏览器偏好和分享目标作为基础材料。

不要检查每个已保存的参考。只检查当前任务需要的。

## 工作流程

1. 关键步骤：警告用户他们必须遵守目标网站的条款才能继续。此工作流仅适用于用户拥有或已获得许可复现的应用和网站。

2. 使用 [$index](../index/SKILL.md#browser-choice) 中的浏览器选择规则打开源 URL。

3. 检查页面是否正确。

- 如果显示错误的页面、被阻止的页面、登录页面、促销页面、加载屏幕、错误页面、应用安装页面或无关的重定向，不要继续。
- 如果页面错误，尝试使用其他可用的浏览器。
- 如果每个浏览器都显示错误的页面，停止并告诉用户你能看到什么。

4. 仔细捕获源页面。

- 从页面顶部开始。
- 以小步幅向下滚动。
- 在每一步，捕获可见的内容。
- 注意任何新的部分、控件、固定元素、动画或延迟加载的资源。
- 继续直到看到完整页面。
- 滚动回顶部并检查是否有任何变化。
- 在 `390 x 844` 的移动设备上重复。

5. 使用浏览器 DOM 工具收集复现源所需的一切。

- 元素
- 组件
- 文本
- 链接
- 按钮和控件
- 状态
- 图像
- 图标
- 字体
- 视频
- SVG
- 样式表
- 颜色
- 间距
- 布局尺寸
- 响应式行为

6. 查找并测试页面交互。

- 使用截图和浏览器 DOM 工具查找可见控件。
- 包括导航、按钮、链接、输入框、菜单、抽屉、模态框、标签页、轮播、悬停状态、固定元素以及用户可以交互的任何其他内容。
- 一次测试一个控件。
- 在测试下一个控件之前返回起始状态。
- 当页面 visibly 变化或浏览器工具显示状态变化时保存结果。

7. 从源页面复制真实资源。

- 如果页面加载了资源，除非浏览器无法访问或保存它，否则将其视为可用。
- 如果页面使用了图像、标志、图标、字体、视频、SVG、精灵图、遮罩、光标或背景图像，将其本地复制。
- 如果图像资源无法复制，使用 ImageGen 以原始截图生成替代方案。
- 如果字体文件无法复制，使用最接近的开源字体匹配。
- 如果图标或字形无法复制，使用最接近匹配的开源图标集。除非它是最接近匹配，否则不要默认使用 Lucide。
- 简要记录你替换的任何资源、字体或图标以及原因。

8. 使用 [local-prototype-preflight](../../references/local-prototype-preflight.md) 创建本地应用。

9. 仅从捕获、复制或从源收集的内容构建。

- 不要添加新的视觉想法。
- 不要使用热链接源资源。
- 当源证明可用时不要猜测。

10. 运行本地应用。

### 在 ChatGPT 工作模式中预览原型

启动 `sites-preview` 不等于验证。验证需要在云浏览器中打开 `http://terminal.local:4173/`，检查渲染后的页面，测试主要交互，检查浏览器控制台错误，并通过设计质量保证。

不要用 HTTP 健康检查、构建成功、预览服务状态或部署成功来替代浏览器验证。如果无法使用云浏览器，报告验证受阻。

对于 ChatGPT 工作模式中的本地原型验证：

1. 如需安装依赖。项目必须有一个 npm `dev` 脚本。
2. `sites-preview` 运行 `npm run dev -- --host 0.0.0.0 --port 4173 --strictPort`。`dev` 脚本必须接受这些参数。
3. 对于产品设计 Vite 启动器，使用 `"dev": "vite"`。配置 Vite 时设置 `server.host: "0.0.0.0"` 和 `server.allowedHosts: ["terminal.local"]`。保留现有 Sites 项目支持的开发脚本；不要替换其运行时。
4. 从站点根目录运行 `sites-preview start "$PWD"`。
5. 在云浏览器中打开 `http://terminal.local:4173/`。不要使用 `localhost`、`127.0.0.1`、`0.0.0.0`、HTTPS 或其他端口。
6. 在报告完成前验证渲染的站点及其主要交互。
7. 保持本地预览对用户开放。除非用户明确要求分享、发布或部署，否则不要部署到 Sites。

11. 将本地应用与原始应用进行比较。

- 检查桌面端。
- 检查移动端。
- 检查你捕获的每个交互。
- 在运行最终质量保证之前修复任何明显的不匹配。

12. 将 [design-qa](../design-qa/SKILL.md) 作为阻塞式构建门禁运行。

- 将质量保证报告保存为项目根目录下的 `design-qa.md`。
- 修复 P0/P1/P2 问题，再次捕获应用，并重复直到质量保证报告显示 `final result: passed`。
- 不要在 P3 打磨上持续循环。将任何剩余的 P3 作为后续迭代备注包含在内。
- 如果源捕获、原型捕获或视觉比较受阻，停止。`design-qa.md` 必须显示 `final result: blocked`。
- 除非 `design-qa.md` 存在并显示 `final result: passed`，否则不要移交。

13. 移交应用或网站

- 仅在 [design-qa](../design-qa/SKILL.md) 通过后才移交。
- 保持原型在本地运行。
- 保持本地预览对用户开放。在 ChatGPT 工作模式中，告诉用户在云浏览器中检查原型；不要提供可点击的本地 URL。在 Codex 桌面版中，提供可点击的本地 URL。除非用户明确要求分享、发布或部署，否则不要部署到 Sites。
- 预览移交后，使用 `critical-overrides.md` 中的共享构建移交。不要添加不同的完成消息。
- 包含 [critical-overrides](../../references/critical-overrides.md#build-handoff) 中的构建后迭代和分享提示。

## 硬性规则

- 首先捕获源证据。在桌面捕获、移动捕获、关键状态以及每个必需的资源、图标、控件标记和字体被捕获或替换之前，不要搭建、编写应用代码、启动服务器或创建本地原型。
- 在从目标捕获每个交互和状态之前不要移交。
- 不要从记忆、仅截图、猜测的 CSS、通用资源或先前的聊天中构建。
- 没有源截图加上该状态的可用 DOM/样式/布局证据，不要实现保存的状态。
- 不要在最终应用中使用热链接源资源。
- 在等待解析资源时，不要创建临时 CSS 图标、文本字形、表情符号标记、占位块或手工制作的 SVG。首先解析资源，然后构建。
- 如果没有批准的浏览器可以捕获有效的源和原型证据，停止并报告设计质量保证阻碍因素。
