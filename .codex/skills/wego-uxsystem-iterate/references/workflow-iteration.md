# 工作流迭代与经验沉淀

> 经验沉淀由信号驱动自动执行，不等待用户触发。目标是让 AI 设计得更好、更符合规范、更有设计感、更符合用户体验。

## 基本原则

- 经验沉淀由 `wego-uxsystem-iterate` 统一承担，主对话或其它技能不得直接修改正式权威源。
- 经验数据位于 `.codex/skills/wego-uxsystem-iterate/experience/`：`evidence.json` 保存事实事件，`EXPERIENCE.md` 是 AI 基于事实推理维护的经验视图。
- 禁止在仓库根目录或其它技能下创建经验目录、记录或副本。
- 事实事件只增不减，不因升级或过时而删除。
- 单场景特例、普通代码错误、需求临时变化、单次视觉微调不进入经验数据。

## 沉淀触发信号

遇到以下可观察信号时自动沉淀，不需要用户要求：

- **用户纠正**：用户明确说"不对"、"不是这样"、"应该是xxx"
- **用户表达偏好**：用户说"我喜欢"、"以后都"、"不要再"
- **返工**：同一问题第二次出现，或验收打回后重做
- **踩坑**：CI 失败、守卫拦截、用户验收打回

没有这些信号的轮次不沉淀。沉淀后告知用户：`🧠已沉淀经验：<简短描述>`。

## 沉淀标准

同时满足以下三条才沉淀：

1. **可复用**：未来的任务中可能再次遇到
2. **可行动**：能指导未来避免问题或做得更好
3. **非冗余**：不是已有正式规则或常识已经覆盖的

## 沉淀流程

1. 识别触发信号，判断是否满足沉淀标准。
2. 在 `evidence.json` 新增事实事件，记录 `id`、`date`、`summary`、`source`、`scene`、`tags`。
3. 阅读 `evidence.json` 中相关事实（包括本次新增和历史相关事件），AI 推理归纳出可操作的经验。
4. 直接写入 `EXPERIENCE.md`：新增经验用 `§` 追加；已有经验需更新时用新表述替换对应条目；经验过时时删除对应条目。
5. 运行 `node scripts/refine-experience.mjs --check` 校验：每条经验必须引用存在的事实 ID、表述不与事实矛盾、格式合规。
6. 告知用户 `🧠已沉淀经验：<简短描述>`。

## EXPERIENCE.md 格式

用 `§`（section sign）分隔多条经验，每条是自然语言段落，包含：

- **经验描述**：可操作的建议或教训，不写空话
- **事实追溯**：标注对应的 evidence ID（如 `[ev-001]`），多条事实用逗号分隔
- **出现次数**：标注累计次数（如 `×3`）
- **最近日期**：标注最近一次出现的日期

示例：

```
# 经验视图

> 由 AI 基于 evidence.json 推理维护，每条经验必须追溯到事实事件。会话前置读取。

§
[工作流] Spec 多轮更新后必须全文检查前后一致性：spec 全部确认后、提交前必须全文搜索关键词统一检查，替换所有旧描述。[ev-001] ×1，最近 2026-08-28
§
[工作流] 经验沉淀必须走标准流程，禁止手动编辑 EXPERIENCE.md：遇到触发信号时写入 evidence.json，AI 推理后直接写入 EXPERIENCE.md，再跑校验脚本确认一致。[ev-003] ×1，最近 2026-08-28
```

容量上限 3000 字符。超限时 AI 自行判断合并相似经验、淘汰过时经验，用一次编辑完成整理。

## 事实一致性校验

`node scripts/refine-experience.mjs --check` 执行以下校验，不生成内容：

1. **事实追溯**：EXPERIENCE.md 中每条经验引用的 evidence ID 必须存在于 evidence.json。
2. **表述一致性**：经验描述不得与对应事实的 summary 存在明显矛盾（关键词比对）。
3. **格式合规**：用 `§` 分隔，每条非空，头部说明完整。
4. **容量检查**：总字符数不超过 3000，超限时警告。

校验失败时必须修正 EXPERIENCE.md 后重新校验，不得跳过。

## 正式升级

升级由用户触发（用户明确要求升级）或 agent 建议（某经验反复出现、影响跨场景时主动建议）。

升级流程：

1. 重新核对经验归属和唯一 `targetAuthority`。
2. 优先修复真实断点。已有规则已经覆盖时，先检查执行入口、消费者、同步和验证，不得默认再增加同义规则。
3. 修改正式规则（AGENTS.md / 技能文件 / 守卫脚本），只同步直接消费者。
4. 运行对应验证，通过后在 evidence.json 中追加升级记录事件。
5. 从 EXPERIENCE.md 中删除对应经验条目。
6. 升级后同类问题再次出现时，立即重新沉淀并复查上次修复内容。

## 文档漂移检查

工作流维护改动权威源后，必须即时执行以下检查，不后置：

1. 按 `sync-matrix.md` 核对本次改动涉及的全部"必改"列。
2. 确认引用的规则锚点（`<!-- rule-id -->`）、文件路径、命令示例与实际一致。
3. 运行 `node scripts/validate-wego-design.mjs --scope=system --strict`，通过后才推送 PR。
4. 经验升级时，核对规则在 AGENTS.md、对应技能 SKILL.md、references/ 中的表述一致性。

## 数据 schema

### evidence.json

```
id, date, summary（事实描述）, source（user-correction/rework/ci-failure/guard-block/acceptance-rejection/user-preference）, scene, tags[]
```

### EXPERIENCE.md

```
头部说明 + § 分隔的多条自然语言经验，每条含：经验描述、[evidence ID]、×次数、最近日期
```
