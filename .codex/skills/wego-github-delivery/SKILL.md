# 微购 GitHub 交付

会话只是执行入口，不是分支。一个可验收交付单元只有一个开放 PR 和一个工作分支。

## 开始交付

1. 先执行 `git pull --rebase origin main`。
2. 对业务页面请求，先运行交付单元核对，覆盖全部 worktree、开放 PR、有效场景认领和未冻结迭代；不得只检查当前目录或 `main`。业务任务使用场景或 routeId 匹配，非业务任务使用明确的改动范围。
3. 核对命中已有交付单元时，切换并复用其分支、worktree 和 PR；不得因新建对话、新 Agent 或新工作目录另建分支。
4. 核对无匹配且无冲突时，才从最新 `origin/main` 创建 `feature/<owner>-<task>` 分支并进入后续流程。
5. 核对出现多个候选、认领与 PR 不一致或无法读取必要信息时，停止后向用户说明阻塞原因；不得自行选择或继续创建迭代。
6. 开始新任务时检查 `.tasks/preview-servers/` 中的本地预览服务记录；进程已失效、PR 已关闭、worktree 已不存在或记录分支与实际分支不一致时，停止残留进程并删除对应记录。不得清理仍在等待用户验收的其它交付单元服务。

## 交付与收口

- 推送分支后创建或更新同一个 PR。业务原型交付时必须同时返回两个可点击验收链接：当前 PR head 分支工作副本启动的本地 HTTP 预览链接，以及已核实的 PR 独立在线预览链接；两个链接必须进入本次任务对应的同一 routeId 或目标入口，并确认包含本次改动。设计系统组件、Token、Preview 或 UI Kit 仍只交付对应的本地 HTTP 预览链接，不以 GitHub Pages 预览作为验收入口。
- 本地预览服务必须从对应 PR head 分支的 worktree 根目录启动，仅绑定 `127.0.0.1`。端口、PID、worktree、分支和 PR 信息记录在 `.tasks/preview-servers/`；同一交付单元已有可用且信息一致的服务时复用，否则先停止旧服务再启动新服务。交付链接前必须实际请求确认 HTTP 200 且目标入口包含本次改动。
- 本地验收服务在回复结束后继续保留，不得按普通临时验证服务立即关闭。只在用户明确验收通过、明确废弃任务、PR 关闭或合并、对应 worktree/分支即将清理，或该服务被同一交付单元的新服务替换时停止；停止后删除服务记录。用户提出验收调整且仍使用同一 worktree、分支和端口时复用原服务，修改后重新验证链接。
- 交付任何未合并 PR 的本地预览前，必须核对主工作目录或对应 worktree 正处于该 PR 的 head 分支，且目标文件和目标入口包含本次改动；交付后不得切换该 worktree 到无关分支。无关任务使用短期独立 worktree。
- 业务原型和设计系统变更只有在用户明确验收通过后才能合并；合并前再次同步 `main` 并完成相应验证。
- 工作流权威源由 `wego-uxsystem-iterate` 维护，可按仓库例外免业务验收直接以 `main` 为目标交付；因分支保护，实际通过短周期 PR 合入，必要检查通过后合并，仍须完成严格系统验证。
- PR 合并或关闭后，先停止对应本地预览服务并删除记录，再删除对应本地与远端分支及干净的关联 worktree；只有 PR 带 `keep-branch` 标签时才保留分支，但预览服务仍默认关闭。
- 无 PR 的工作分支不得在任务结束后悬空：继续交付则创建 PR，明确废弃则删除。

## 边界

- 不替代 `wego-product`、`wego-design` 或 `wego-uxsystem-iterate` 对内容范围的判断。
- 不把推送、创建 PR 或通过检查视为用户验收。
- 不删除 `main`、当前正在使用的分支、带 `keep-branch` 标签的分支，或有未提交改动的 worktree。
- 不停止仍有开放 PR 且正在等待用户验收、并与记录 worktree 和分支一致的本地预览服务。
- 分支盘点只输出并执行明确的保留、收口或清理动作；无法归属的分支先关联到 PR 或关闭，不再长期保留为“待观察”。
