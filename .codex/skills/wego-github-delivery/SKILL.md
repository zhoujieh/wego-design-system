# 微购 GitHub 交付

会话只是执行入口，不是分支。一个交付单元固定复用一个工作分支和 worktree；进入正式验收后最多只有一个开放 PR。

## 开始交付

1. 先执行 `git pull --rebase origin main`。
2. 对业务页面请求，先运行交付单元核对，覆盖全部 worktree、开放 PR、有效场景认领和未冻结迭代；不得只检查当前目录或 `main`。业务任务使用场景或 routeId 匹配，非业务任务使用明确的改动范围。核对时逐个检查开放 PR 分支相对 `main` 的落后情况；接手落后分支先 merge 同步最新 `main`（含冲突解决与生成物再生成）再继续，等待验收中的 PR 同样适用，落后超过 20 个提交时先向用户报告。
3. 核对命中已有交付单元时，切换并复用其分支、worktree 和已有 PR；不得因新建对话、新 Agent 或新工作目录另建分支。
4. 核对无匹配且无冲突时，才从最新 `origin/main` 创建 `feature/<owner>-<task>` 分支并进入本地迭代；首次开工不自动创建 PR。
5. 核对出现多个候选、认领与 PR 不一致或无法读取必要信息时，停止后向用户说明阻塞原因；不得自行选择或继续创建迭代。
6. 开始新任务时检查 `.tasks/preview-servers/` 中的本地预览服务记录；进程已失效、worktree 已不存在、记录分支与实际分支不一致，或记录已关联且 PR 已关闭/合并时，停止残留进程并删除对应记录。不得把“尚未创建 PR”视为残留，也不得清理仍在本地迭代或等待验收的其它交付单元服务。

## 两阶段状态

### 本地迭代中（默认）

- 新任务、首次实现和后续小问题调整默认停留在本地迭代中。
- 允许修改、轻量验证、真实浏览器检查和按一组相关改动创建本地 checkpoint commit；禁止自动推送、创建或更新 PR、触发在线预览。
- 有可视内容时，从当前任务 worktree 启动或复用本地 HTTP 预览，只返回本地链接；无可视入口的工作流或文档维护直接报告验证结果。
- 每次结果必须标明：`当前状态：本地迭代中（未推送）`。

### 正式验收中

只有用户明确表达以下意图之一，才进入正式验收：提交、推送、创建/更新 PR、发在线预览，或明确说明“这一轮改完了，可以验收”。“改好了”“继续”“再调整一下”等普通反馈不构成提交授权，Agent 不得自行判断任务已完成而推送。

进入正式验收后：

1. 运行与范围相称的完整严格验证；业务原型同时执行 `submit-prototype`。
2. 集中提交尚未提交的改动，推送当前分支并创建或更新同一个 PR。
3. 业务原型返回本地 HTTP 与 PR 独立在线预览两个链接；设计系统组件、Token、Preview 或 UI Kit 仍只返回本地 HTTP 预览。
4. 每次结果必须标明：`当前状态：正式验收中（PR #<编号>）`。

PR 已存在时，用户继续提出小问题仍先回到本地迭代，累计完成一轮后再由用户明确要求更新 PR；不得每改一个问题就自动推送。

回复结束、任务暂停或会话结束时，任务 worktree 不得遗留未提交改动：成组改动提交 checkpoint commit，零散改动还原或登记到任务记录；未提交改动不得跨会话存活。

## 预览服务

- 本地预览服务从当前交付单元 worktree 根目录启动，仅绑定 `127.0.0.1`。端口、PID、worktree、分支、阶段、可空 PR 编号和目标入口记录在 `.tasks/preview-servers/`；记录不得提交。
- 本地迭代阶段核对服务 worktree 当前分支与任务分支一致；正式验收阶段还必须核对与 PR head 分支一致。交付链接前实际请求确认 HTTP 200 且目标入口包含本次改动。
- 同一交付单元已有可用且信息一致的服务时复用，否则先停止旧服务再启动新服务。进入正式验收后更新原记录的阶段和 PR 编号，不为同一任务重复启动服务。
- 本地服务在回复结束、对话结束和等待用户反馈期间继续保留。只在用户明确验收通过、明确废弃任务、任务分支/worktree 即将清理、PR 关闭或合并，或服务被同一交付单元的新服务替换时停止并删除记录。

## 合并与收口

- 业务原型和设计系统变更只有在用户明确验收通过后才能合并；合并前再次同步 `main` 并完成相应验证。
- 工作流权威源由 `wego-uxsystem-iterate` 维护，免业务验收，也免明确提交授权门禁；完成改动并运行 `node scripts/validate-wego-design.mjs --scope=system --strict` 通过后，直接推送创建短周期 PR，必要检查通过后自动合并到 `main` 并删除分支；CI 失败时停止并报告原因等用户处理。业务原型和设计系统组件、Token、Preview、UI Kit 变更不适用本例外。
- PR 合并或关闭后，先停止对应本地预览服务并删除记录，再删除对应本地与远端分支及干净的关联 worktree；只有 PR 带 `keep-branch` 标签时才保留分支，但预览服务仍默认关闭。
- 合并冲突涉及生成物（`wego-app/js/routes.js`、`wego-app/lib/`、`components.css`）时，不得手工编辑冲突标记：先取任一侧版本，运行对应生成脚本（`build-routes.mjs` / `sync-wego-app-lib.mjs`）重新生成后提交。
- 没有 PR 的工作分支允许在本地迭代期间保持；用户明确废弃任务或确认不再继续时，停止服务、释放认领并删除分支/worktree。不得因单次回复结束而强制创建 PR 或删除仍在继续的任务。

## 边界

- 不替代 `wego-product`、`wego-design` 或 `wego-uxsystem-iterate` 对内容范围的判断。
- 不把本地预览、完成修改、通过检查、创建 checkpoint commit 或用户查看页面视为提交授权或正式验收。
- 不删除 `main`、当前正在使用的分支、带 `keep-branch` 标签的分支，或有未提交改动的 worktree。
- 不停止状态仍为本地迭代或正式验收、且与记录 worktree 和分支一致的本地预览服务。
- 分支盘点只输出并执行明确的保留、收口或清理动作；无法归属的分支先关联到交付单元或关闭，不再长期保留为“待观察”。
