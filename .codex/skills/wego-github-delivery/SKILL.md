# 微购 GitHub 交付

会话只是执行入口，不是分支。一个可验收交付单元只有一个开放 PR 和一个工作分支。

## 开始交付

1. 先执行 `git pull --rebase origin main`。
2. 对业务页面请求，先运行交付单元核对，覆盖全部 worktree、开放 PR、有效场景认领和未冻结迭代；不得只检查当前目录或 `main`。业务任务使用场景或 routeId 匹配，非业务任务使用明确的改动范围。
3. 核对命中已有交付单元时，切换并复用其分支、worktree 和 PR；不得因新建对话、新 Agent 或新工作目录另建分支。
4. 核对无匹配且无冲突时，才从最新 `origin/main` 创建 `feature/<owner>-<task>` 分支并进入后续流程。
5. 核对出现多个候选、认领与 PR 不一致或无法读取必要信息时，停止后向用户说明阻塞原因；不得自行选择或继续创建迭代。

## 交付与收口

- 推送分支后创建或更新同一个 PR，并提供该 PR 的独立预览入口。
- 业务原型和设计系统变更只有在用户明确验收通过后才能合并；合并前再次同步 `main` 并完成相应验证。
- 工作流权威源由 `wego-uxsystem-iterate` 维护，可按仓库例外免业务验收直接以 `main` 为目标交付；因分支保护，实际通过短周期 PR 合入，必要检查通过后合并，仍须完成严格系统验证。
- PR 合并或关闭后，默认删除对应本地与远端分支；只有 PR 带 `keep-branch` 标签时才保留。先处理干净的关联 worktree，再删除分支。
- 无 PR 的工作分支不得在任务结束后悬空：继续交付则创建 PR，明确废弃则删除。

## 边界

- 不替代 `wego-product`、`wego-design` 或 `wego-uxsystem-iterate` 对内容范围的判断。
- 不把推送、创建 PR 或通过检查视为用户验收。
- 不删除 `main`、当前正在使用的分支、带 `keep-branch` 标签的分支，或有未提交改动的 worktree。
- 分支盘点只输出并执行明确的保留、收口或清理动作；无法归属的分支先关联到 PR 或关闭，不再长期保留为“待观察”。
